# 插件中心与应用中心审核

:::info 管理员操作
进入“设置 → 插件中心”。管理员审核的是用户提交的发布快照，不是用户可随时变化的个人目录。
:::

## 审核发布

在“上架审核”中打开待审发布，核对：

- 发布者、能力类型、发布序号和发布说明。
- 包内文件列表、可执行位和内容 SHA-256。
- Manifest、Skill 正文和 Logo。
- MCP server、脚本、外部连接、环境变量、凭据与依赖下载等风险声明。

每个新发布都必须单独审核。通过前系统再次校验快照完整性。

## 审核应用中心版本

应用中心的待审版本会同时显示应用创建者、普通或交互式类型、版本号、版本说明和使用方式。打开审核详情后检查应用指令、插件与 Skill 名称、知识库和 MCP 数量；交互式应用还会显示包内文件路径。

“应用安装包”会复制为使用者独立维护的应用，“应用服务”会使用创建者维护的资源和凭据。交互式应用不能以上传安装包的方式分发，只能作为应用服务。确认发布说明与实际能力相符，并评估指令、外部连接、数据范围和所选使用方式后再通过；拒绝时必须填写原因。

## 通过或拒绝

- 通过：该不可变发布成为当前版本；首次通过使条目公开上架。
- 拒绝：必须填写明确原因，不影响之前已通过版本和已有安装。

管理员发布者可以审核自己的发布，但仍应遵循组织的双人复核政策（如有）。

## 停用与恢复

发现风险时可以在“全部上架项”中停用条目并填写原因。停用后：

- 插件中心隐藏条目。
- 阻止新安装和更新。
- 所有已安装副本不能开始新的任务。
- 已经运行的轮次继续使用启动时快照，不被强行改写终态。

恢复后条目重新公开，已有安装可用于后续新任务。

应用中心使用独立的上架状态。管理员下架应用时必须填写原因；新的安装和服务启动会被阻止，既有任务历史保留。已经独立安装的应用包不会被远程删除，仍按其个人资源状态和平台能力治理规则运行。恢复上架后，符合授权条件的用户可以重新安装或使用服务。

## 下架与停用的区别

- 发布者下架：不再接受新安装，但已有安装可以继续运行和显式更新。
- 管理员停用：风险治理状态，已有安装的新任务也被阻止。

## 审计与隐私

审核、拒绝、撤回、上下架、停用和恢复都会写入脱敏审计。应用审核只展示提交版本所需的指令和资源摘要；治理权限不授予管理员读取或修改用户未提交的个人插件、Skill 或应用草稿。
