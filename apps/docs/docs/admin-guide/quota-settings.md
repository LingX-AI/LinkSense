# 额度管理

管理员进入“设置 → 额度管理”，设置 credits 换算价格和全体成员统一使用的周额度标准。

## Credits 换算

设置 1 credit 对应的美元金额，默认是 0.01 美元。例如，一次调用费用为 0.25 美元时，将消耗 25 credits。金额必须大于 0，最多支持 6 位小数。

模型单价仍在模型设置中配置，单位为美元/百万 Token。费用根据调用量及当时的模型价格计算，credits 按记账时的换算价格记录。修改换算价格只影响之后记录的消费，不重新计算已经记录的 credits。消耗保留 6 位小数，不足精度的部分向上取整。前端展示剩余 credits 时截去小数位，实际余额和使用判断仍保留小数精度。

## 成员周额度

成员周额度是之后由管理员创建、Excel 导入或自主注册成员的统一默认值。输入正数，最多支持 6 位小数；留空表示不限额。周额度按系统时区在每周一零点自动重置。

直接保存只更新默认值，不覆盖已有成员的个人周额度。已有成员仍可在“用户与用户组 → 用户”中单独或批量调整。开放注册开关位于“系统设置 → 开放注册”，但自主注册用户不再使用另一套额度标准。

## 一键重置与应用到全员

额度管理提供两个即时批量操作。点击按钮后先弹窗确认；取消弹窗不会修改额度。

- **重置全员额度**：把所有已有成员的周额度恢复到各自现有限额的 100%。该操作不改变成员的限额；不限额成员仍保持不限额。
- **应用限额到全员**：保存表单中的成员周额度，并立即覆盖所有已有成员的个人周额度，包括曾单独调整过的值。留空会将所有成员设为不限额。该操作不清零已经使用的额度，也不保存换算价格表单中的其他未提交修改。

两个操作都包含正常和已禁用成员，且不会改变账号状态。历史消费记录会保留。重置后发生的消费继续扣减，日历周重置规则也保持不变。

如果要让全部成员使用新限额并恢复到 100%，请先“应用限额到全员”，再“重置全员额度”。

周额度耗尽后，用户不能发起新任务或后续请求。已经运行的任务会继续完成，最终消耗可能超过上限。调整周额度不会删除或重新计算已经记录的 credits。

Token 和美元费用统计继续保留，额度管理不提供充值或支付功能。
