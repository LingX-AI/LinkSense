# 额度管理

管理员进入“设置 → 额度管理”，设置 credits 换算价格、组织成员初始额度和开放注册用户额度。

## Credits 换算

设置 1 credit 对应的人民币金额，默认是 0.01 元。例如，一次调用费用为 0.25 元时，将消耗 25 credits。金额必须大于 0，最多支持 6 位小数。

模型单价仍在模型设置中配置，单位为元/百万 Token。费用根据调用量及当时的模型价格计算，credits 按记账时的换算价格记录。修改换算价格只影响之后记录的消费，不重新计算已经记录的 credits。消耗保留 6 位小数，不足精度的部分向上取整。前端展示剩余 credits 时截去小数位，实际余额和使用判断仍保留小数精度。

## 两类成员

- **组织成员初始额度**：给之后手动创建或导入的每位成员预置个人额度。修改默认值不会覆盖已有成员。
- **开放注册用户额度**：给每位自助注册用户设置个人额度。修改此处额度会同步已有自助注册用户，包括曾单独调整过额度的用户。修改换算价格或组织成员默认值不会触发这种覆盖。

开放注册开关仍在“系统设置 → 开放注册”，与额度设置独立。已有用户的单独调整和批量设置仍在“用户组与用户 → 用户”。

## 一键重置与批量应用

额度管理提供三个批量操作。点击按钮后先弹窗确认，确认后立即生效，无需设置执行时间；取消弹窗不会修改额度。

- **重置全部组织成员额度**：把所有组织成员的周、月、总剩余额度恢复到各自现有限额的 100%。
- **重置全部注册成员额度**：把所有自助注册成员的周、月、总剩余额度恢复到各自现有限额的 100%。
- **保存并应用限额到全部组织成员**：把表单中的组织成员限额保存为默认值，并立即覆盖所有已有组织成员的对应限额，包括单独调整过的限额；留空的项目取消限制。确认弹窗会展示即将应用的限额。此操作不清零已经消耗的额度，也不保存换算价格或注册成员部分的其他修改。

批量操作同时包含正常和已禁用的目标成员，不改变账号状态。重置不会改变用户限额，不限额的项目保持不限额，当前表单中未保存的修改不参与重置。重置保留历史消费记录，之后的消费继续扣减；周、月额度仍按原有日历周期自动恢复。

如果要让全部组织成员使用新限额并恢复到 100%，先保存并应用新限额，再重置全部组织成员额度。

## 周额度、月额度和总额度

两类成员均可分别设置三个上限，单位为 credits，支持正数和最多 6 位小数。每项留空表示不限制该项，全部留空表示不限额。开放注册额度由非空改为空时，也会取消已有自助注册用户的对应限制。

- 周额度：按系统时区，在周一零点重置。
- 月额度：按系统时区，在每月一日零点重置。
- 总额度：累计上限，不自动重置。

一次消费同时计入本周、本月和累计用量，不重复扣减。任意一项额度耗尽后，用户不能发起新任务或后续请求。已运行的任务继续完成，最终消耗可能超过上限。调整额度上限不会清零已经消耗的 credits。

Token 和人民币费用统计继续保留，额度管理不提供充值或支付功能。
