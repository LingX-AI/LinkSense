# 系统健康与索引重建

:::info 管理员操作
“设置 → 系统健康”是只读诊断页；只有明确提供的维护动作会改变状态。
:::

## 健康项目

页面展示：

- API、数据库和 Redis。
- 本地密码登录保护与认证邮件。
- 知识库文档解析。
- 知识库检索与索引。
- 可选结果重排。
- runner、工作区可读写状态。
- 权威运行槽、实际运行轮次、恢复状态、子进程数和并发上限。
- Docker 部署中 API、Runner、worker、Web、网关、PostgreSQL 和 Redis 等容器的 CPU、内存、PID 与运行状态。

页面只显示脱敏摘要和检查建议，不显示连接串、密码、Token、密钥、Redis key 或完整内部日志。

## 理解总体状态

- liveness 表示 API 进程仍在运行。
- readiness 表示关键依赖是否可以承接完整流量。
- MinIO 等必要存储失败会使 readiness 不可用，但进程继续探测。
- Docling 或知识检索外部服务不可用会单独标记相应能力，不一定使整个 LinkSense 不可用。
- Ranker 未配置是合法状态，失败时使用 RRF。

## 服务资源占用

“服务资源占用”展示最近一次可用的 Docker 容器快照。无法观测通常表示 Runner 控制器没有可用的 Docker socket 或权限；它不等同于所有容器已经停止。资源卡只用于诊断，不会从页面重启或停止容器。

## 磁盘占用

“磁盘占用”位于顶部健康摘要，只展示当前部署的总占用。它包含所有用户的项目空间、任务产物与附件、运行环境与缓存，以及数据库、知识库索引、备份、日志和服务程序。已完成或归档任务仍保留的文件也会计入。

统计使用文件系统已分配空间，稀疏文件按实际占用计算；共享目录、硬链接和镜像层只计一次，实际保留的不同副本分别计入。这不是服务器整块磁盘的使用量，也不包含其他部署、全局构建缓存或无法确认归属的历史镜像。多个部署共同挂载的存储无法单独归属时会列为未统计。外部服务器上的数据库、对象存储和索引不计入本机占用，应在相应服务单独查看。

系统启动后先采集一次，此后每小时在后台更新；上次扫描未结束时不会并发启动。大目录扫描有独立的时间与资源限制。其他健康信息先正常显示，磁盘占用在首次完整统计返回后自动加入顶部摘要；扫描未完成或结果不完整时，不显示磁盘占用，也不把残余数据当作总量。最近统计时间可通过悬停查看。采集不阻塞健康检查或任务执行，失败不直接改变服务就绪状态。

Docker 部署使用已有 Worker 镜像启动只读、无网络的临时采集容器，不读取文件内容，完成后移除。需要现有 Docker socket 权限及允许只读扫描的容器能力；存储驱动无法提供镜像层或可写层位置时，相应分类显示未统计。本机进程部署暂时无法提供完整的部署磁盘统计。

本功能没有数据库迁移，也不搬迁、清理或改写已有用户文件。更新 Runner、API 和 Web 后即可读取既有空间；不需要重新创建任务、项目或应用。

## 清理失败资源

任务或能力删除后的异步清理多次失败时，健康页会列出资源类型、清理阶段、稳定原因和尝试次数。可以重试单项或全部失败项；系统会重新核对状态，仍在使用的目标任务会延后清理，其他运行中任务不会被中断。

路径边界、权限或运行状态无法确认时，不要手工删除受控目录。先按页面原因修复部署权限或 Runner，再从健康页重试。

## 全量重建知识库索引

切换 Embedding 模型或发现部署范围索引不一致时，页面会提示重建：

1. 确认模型与维度配置已经稳定。
2. 选择全量重建并阅读影响。
3. 在维护窗口启动。
4. 持续查看进度和失败数。
5. 完成后验证知识库检索状态。

重建有部署级并发上限，失败项会保留可重试状态。不要通过重复点击并行启动多个重建。

## 故障升级

按建议检查项由有部署权限的人员处理环境变量、网络或外部服务。健康页不会自动启动、重建或管理 Docling、Elasticsearch、模型服务等外部容器。
