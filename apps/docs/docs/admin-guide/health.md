# 系统健康与索引重建

:::info 管理员操作
“设置 → 系统健康”是只读诊断页；只有明确提供的维护动作会改变状态。
:::

## 健康项目

页面展示：

- API、数据库和 Redis。
- 本地密码登录保护与认证邮件。
- 知识库文档解析。
- 知识库检索与索引。
- 可选结果重排。
- runner、工作区可读写状态。
- 权威运行槽、实际运行轮次、恢复状态、子进程数和并发上限。
- Docker 部署中 API、Runner、worker、Web、网关、PostgreSQL 和 Redis 等容器的 CPU、内存、PID 与运行状态。

页面只显示脱敏摘要和检查建议，不显示连接串、密码、Token、密钥、Redis key 或完整内部日志。

## 理解总体状态

- liveness 表示 API 进程仍在运行。
- readiness 表示关键依赖是否可以承接完整流量。
- MinIO 等必要存储失败会使 readiness 不可用，但进程继续探测。
- Docling 或知识检索外部服务不可用会单独标记相应能力，不一定使整个 LinkSense 不可用。
- Ranker 未配置是合法状态，失败时使用 RRF。

## 服务资源占用

“服务资源占用”展示最近一次可用的 Docker 容器快照。无法观测通常表示 Runner 控制器没有可用的 Docker socket 或权限；它不等同于所有容器已经停止。资源卡只用于诊断，不会从页面重启或停止容器。

## 清理失败资源

任务或能力删除后的异步清理多次失败时，健康页会列出资源类型、清理阶段、稳定原因和尝试次数。可以重试单项或全部失败项；系统会重新核对状态，仍在使用的目标任务会延后清理，其他运行中任务不会被中断。

路径边界、权限或运行状态无法确认时，不要手工删除受控目录。先按页面原因修复部署权限或 Runner，再从健康页重试。

## 全量重建知识库索引

切换 Embedding 模型或发现部署范围索引不一致时，页面会提示重建：

1. 确认模型与维度配置已经稳定。
2. 选择全量重建并阅读影响。
3. 在维护窗口启动。
4. 持续查看进度和失败数。
5. 完成后验证知识库检索状态。

重建有部署级并发上限，失败项会保留可重试状态。不要通过重复点击并行启动多个重建。

## 故障升级

按建议检查项由有部署权限的人员处理环境变量、网络或外部服务。健康页不会自动启动、重建或管理 Docling、Elasticsearch、模型服务等外部容器。
