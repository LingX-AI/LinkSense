# 共享应用与配置外部访问

## 组织内共享

在“我的应用”的应用卡片三点菜单中选择“组织内共享”，添加一个或多个用户或用户组，并选择使用方式：

- **应用安装包**：仅普通应用可用。接收者安装为自己的独立应用，并自行配置凭据、知识库和外部连接。
- **应用服务**：接收者安装后使用创建者维护的应用资源和已配置凭据。交互式应用只支持此方式。

普通应用可以同时提供两种方式。被共享者需要明确安装后才能使用；服务使用者不能因此浏览应用指令、创建者凭据或应用知识库中的文档。

取消共享会阻止新的服务安装和使用，但不会删除已经安装的独立应用包。既有任务及其历史结果仍属于原使用者。用户同时通过用户和用户组获得授权时，移除一个授权来源不一定立即失去访问。

### 更新已共享的交互式应用

“发布更新”或“更新应用包”成功后，新版本只对创建者生效。组织内共享和应用中心需要分别更新，其他用户手动安装后才会使用新版；草稿编辑不会提前发布。

1. 在开发界面点击“发布更新”并确认，或从应用卡片菜单选择“更新应用包”，导入新版 ZIP。
2. 确认新包所需资源均已配置，并填写更高的 `x.x.x` 正式版本号。
3. 再打开“组织内共享”并点击“保存共享”，向接收者提供本次已发布版本。窗口默认选中原来的共享用户和用户组，可以按需调整。

接收者看到“有更新”后，需要手动安装。该用户的此应用还有任务运行时，须停止相关任务或等待完成后再安装。安装成功后按以下规则使用：

| 使用场景 | 使用的版本 |
| --- | --- |
| 新建任务 | 当前已安装版本；发现更新不等于已经安装。 |
| 在已有任务中发起下一次执行 | 当前已安装版本，保留已有对话和工作文件。 |
| 任务已经开始执行 | 保持本次已采用的版本，不在执行中途切换，也不能同时安装更新。 |
| 只打开或刷新历史任务，没有提交请求 | 不会触发执行或自动安装更新。 |

历史结果不会被新版本改写。任务文件和对话上下文会保留；若安装失败，原已安装版本保持不变。

应用中心提供当前已审核上架的版本，用户仍需手动安装。发布应用或“保存共享”不会同时更新应用中心，需要单独提交并完成审核上架。

## 外部 iframe 访问

只有应用创建者可以打开“更多操作 → 外部访问”。配置步骤为：

1. 添加允许嵌入的网站来源，每行一个且不能重复；生产环境使用 HTTPS，本地调试可使用 localhost 或 127.0.0.1 的 HTTP 地址。
2. 选择“需要认证”或“不需要认证”。
3. 为每个来源按需配置最多 4 个内置问题，每个问题最多 500 个字符。
4. 保存安全配置并复制对应来源的 iframe 地址或代码片段。
5. 在宿主网站完成集成测试后，再开启“启用外部访问”。

允许来源必须与实际宿主页面的协议、主机和端口完全一致。关闭外部访问后，新的外部请求和已经打开的外部会话都会失效。

### 外部访问如何更新版本

外部访问使用创建者当前的正式版，无需等待重新组织内共享或应用中心上架，也不要求外部用户手动安装。

- 全新的外部会话从创建者当前正式版开始。
- 已有外部用户在新建任务或继续对话时，如果该用户在此应用中的全部任务均已结束，会在启动前自动更新到创建者当前正式版。
- 只要还有任务正在启动、运行或停止中，就继续使用原版，不影响正在运行的任务。更新进行期间，其他新的启动请求会提示稍后重试。
- 更新失败时，本次启动会提示错误，原版本、对话和工作文件保留；再次启动时重新检查更新。
- 仅打开页面、刷新页面或恢复会话不会触发更新；未发布草稿不影响外部用户。

需要认证的访问和公开访问均遵循这些规则。组织内共享及应用中心仍采用手动安装规则。

## 需要认证

受信任业务后端使用 App ID 与 App Secret 申请短时 ticket，业务前端只把 ticket 交给 iframe。App Secret 只能保存在服务端；不要放入浏览器代码、URL、日志或截图。轮换 Secret 会立即使旧 Secret 及相关未使用 ticket 失效。

详细请求流程、用户身份和 `postMessage` 协议见[嵌入 LinkSense 应用](../../developer-guide/embed-application.md)。

## 不需要认证

公开模式不要求业务后端签发 ticket，但仍只接受允许来源。任何能访问该页面的人都可能创建应用会话，因此只适用于无需识别外部用户、风险可控的内容；不要把公开模式当作访问控制。
