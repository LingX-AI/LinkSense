# Organize tasks with projects

Projects keep related tasks and files together. Tasks in the same project share its files. Personal tasks without a project share a common workspace. Your personal tasks also share installed plugins, Skills, tools, and sign-in state.

## Create a project

1. Click **+** beside Projects in the sidebar and enter a name.
2. Select the project above the composer when creating a task.
3. Send a message. Other tasks in the project can continue using these files.

Each task can belong to one project. Expand or collapse projects, drag them to reorder them, and pin individual tasks. Names and assignments are saved to your account; expansion preferences stay in the current browser.

## Move a task

Drag a task onto a project or choose Move to project from its menu. Finish running work, queued messages, pending plans, and active goals before moving it.

New messages use the destination project's files. Files in the original project remain there, and historical attachments remain accessible. Uploaded attachments that have not been sent are also retained.

A task branched from a reply inherits the project and shares its files. Each task keeps its own message history.

## Delete tasks and projects

Deleting a task removes its message history and keeps project files. Deleting a project moves its tasks to the common workspace and keeps the original files and historical attachments. Delete files separately when you want to remove them.

Application services have their own work environment. Grouping an application task into a project organizes the task without moving service files or sign-in state into your personal workspace.

## Runtime and historical files

Your personal tasks use one personal environment. An idle environment stops to save resources while retaining files and settings, then starts automatically when needed. Enable Keep running in settings if it needs to stay available.

Files from tasks created before the upgrade are retained in the project's `imports/task-id` directory. Historical attachments remain accessible from the message history.
