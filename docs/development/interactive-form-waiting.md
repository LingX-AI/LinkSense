# 交互表单等待与推荐答案

`request_user_form` 继续使用现有链路：Core MCP 工具调用 Runner HTTP 表单服务，执行池等待现有请求的响应。API 持久化表单，在用户提交或采用推荐答案后，通过原有响应接口释放这次等待。不启用原生 elicitation 或动态工具，不启动新回合，不重放任务。

## 等待规则

- `waiting_policy: { kind: "required" }`：必答表单没有业务截止时间，只接受有效回答。页面不显示跳过按钮。未声明策略时同样按必答处理。
- `waiting_policy: { kind: "optional", recommendation: { ... } }`：可以跳过的表单必须为每个字段提供符合字段约束的推荐值。API 首次登记表单时记录 180 秒后的固定截止时间；到期后使用持久化的推荐答案继续原任务。
- `purpose: "approval"` 只允许必答策略。默认值、推荐答案、超时和取消均不能表示用户授权。

等待策略作用于整张表单。包含必须回答问题的表单应使用必答策略。用户仍可主动停止任务；运行进程结束、回合终止等原有生命周期行为继续生效，等待不会在新进程中重建或重放。

推荐答案在页面中明确展示并填入控件，用户可以修改后提交，也可以点击“使用推荐答案”。只有截止时间前被服务端接收的有效提交才优先于推荐答案。编辑、聚焦、刷新或重新打开页面不会延长截止时间；草稿不会被自动提交。截止时间后到达的提交按推荐答案处理。

例如，一个可跳过的选择问题：

```json
{
  "message": "请选择报告范围，建议先生成摘要。",
  "purpose": "input",
  "waiting_policy": {
    "kind": "optional",
    "recommendation": { "scope": "summary" }
  },
  "fields": [{
    "id": "scope",
    "label": "报告范围",
    "control": "single_select",
    "required": true,
    "options": [
      { "value": "summary", "label": "摘要" },
      { "value": "full", "label": "完整报告" }
    ]
  }]
}
```

## 持久化与投递

表单记录新增可空 `form_waiting_policy_json` 和 `response_source`。前者保存策略和推荐内容；后者区分用户提交与超时采用推荐答案。自动处理后的页面显示“超时后已采用推荐答案”，审计仅记录来源等必要元数据。

后台复用现有 BullMQ 维护队列，每秒扫描到期表单，每轮最多 25 条；按表单 ID 创建唯一投递作业。关闭页面不影响处理。实际投递时间受队列负载与服务可用性影响。

服务端在事务中锁定会话和表单，固定首个被接受的答案及其来源。投递调用现有 Runner 响应接口；用户提交、超时扫描和重复作业不会重复推进同一个请求。投递失败仍保留已选答案，重试沿用原请求 ID，不替换答案，也不重试整个 Codex 回合。超过 30 秒的未完成投递可以被重新领取，每次领取都刷新时间，防止并发重复领取。

自动投递最多尝试 5 次，退避间隔从 5 秒开始指数增加，失败作业保留在维护队列。此类失败不会伪装成已回答，也不会无限重新入队；运维处理需恢复相关服务后重试原投递作业。任务已经停止等失效请求不再投递。

表单 HTTP 连接关闭 undici 的请求头和响应体等待截止，保留任务取消信号。Codex 0.154.0 的外层 MCP 配置只接受有限时长，Core 工具保护时限设为 100 年，以避免实际的人机等待被截断；这仍是传输层的有限上限。没有使用可能导致 Rust 时间溢出的最大数值。100 年取值参考 [Rust Instant 的跨平台时长说明](https://doc.rust-lang.org/std/time/struct.Instant.html#os-specific-behaviors)。其他 Core 服务仍执行各自的有限请求时限。

## 升级与验证

迁移 `20261027090000_form_waiting_policy` 只新增两个可空字段和到期查询索引，不删除或转换历史数据。旧记录没有策略时按必答处理，不凭空生成推荐答案；已结束表单仍按原有结果展示。

先执行迁移，再同步更新 API、Runner/Worker 与 Web。既有运行进程中的表单仍遵循该进程的代码，不应假定升级可以恢复已经丢失的等待请求。

相关单元测试覆盖推荐答案完整性与约束、必答持续等待、三分钟边界、提交与超时竞争、重复领取、失败后保留答案、旧记录回答、权限与停止状态、队列投递，以及页面倒计时、草稿和六语言提示。验证不依赖真实等待三分钟或真实模型调用。
