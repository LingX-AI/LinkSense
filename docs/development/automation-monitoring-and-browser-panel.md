# 自动化监控与浏览器人工接管

## 操作入口

自动化编辑页的「结束规则与会话」提供停止条件、最多自动触发次数和每次新会话。条件由 Agent 判断；次数上限与原有到期日期提供确定性边界。达到条件后，不再派发后续运行，当前原生 turn 正常收尾后暂停计划，可手动恢复。达到次数上限后需先提高或取消上限，历史次数不清零。

次数统计的是持久领取的自动触发次数，包括派发失败；手动「立即执行」不计次数，也不能通过工具停止计划。重复调度、重启和原有派发恢复使用同一运行与会话 ID，不重复增加次数。每次新会话只隔离聊天历史，仍使用用户原有运行环境和所选模型；「查看任务」打开最近一次已接受派发的运行会话。

普通任务页右上方的显示器图标打开浏览器面板。先让 Agent 打开网页，再查看同一个隔离浏览器的画面和地址。画面按需及约 1.5 秒刷新，不是连续视频；面板不会打开另一台浏览器或继承本机浏览器登录状态。

「接管浏览器」后可点击页面、滚动、输入文字和发送导航键，另提供 Enter、Tab、Escape 按钮。输入文字后焦点保留。接管期间托管浏览器命令拒绝 Agent 操作，当前 AI turn 的其他工作仍按原生协议执行。「交还 Agent」只交还页面控制；若 turn 已结束，可点击「交还并继续任务」，通过原有消息发送流程继续。已有草稿、附件、引用或 Goal 模式时，继续提示会先加入输入框，保留现有内容。

## 权限、并发与生命周期

- 自动化计数和停止状态在计划行锁下更新；排队取消、恢复输入框、转为 steer、禁用用户和部署收尾均结算已消费次数。停止中的计划在数据库筛选阶段排除，不占满调度批次。
- `stop_scheduled_monitor` 不接受资源 ID。宿主绑定当前活动用户、会话和投影 turn，API 再校验真实自动化运行及创建时的停止条件。普通消息、手动试跑、Plan 模式和其他用户不能暂停计划。
- 浏览器所有请求经过 API 身份、任务归属及应用运行权限检查，再由控制器路由到正确用户 Worker。Plan 与归档任务不能接管或输入，原有 Plan 浏览器限制在任务结束后仍保留。
- 一个浏览器只有一个人工控制令牌。画面查询不会续期控制权；可见面板每 10 秒续期，失联约 30 秒自动失效。关闭面板、切换任务会主动释放；释放失败仍有超时兜底。
- 浏览器命令使用现有 `proper-lockfile` 跨进程互斥，保留原 CLI 会话工作目录。单轮结束时保留浏览器，后续消息沿用同一会话；面板操作会刷新空闲计时。沿用运行环境的空闲回收配置（默认 15 分钟），运行环境关闭或回收时强制清理，不保留孤立浏览器。
- 画面和输入只通过已授权 API 传输，响应禁用缓存；不向 Web 暴露 CDP、Runner 密钥或其他窗口的控制令牌，不把截图或输入写入审计内容。不同面板的缓存与控制状态隔离。

## 升级与兼容性

先应用 `20261023100000_add_automation_monitoring`，再部署 API、Runner/Worker 和 Web。迁移只新增两列可空 JSONB，保留既有表、数据、索引和约束；不要修改已应用迁移。原计划的 `new_task` 仍是创建一次后复用，不改变原语义。旧配置和旧运行的空字段继续可读、可编辑、可执行，默认不限次数、复用原任务；次数从升级后的自动触发开始记录。

更新前等待运行任务正常结束，使用新 Worker 镜像并刷新前端。已有用户的内置 MCP 环境配置在下次任务配置时更新；不要通过自定义整轮重试、重放输入或临时清空数据库完成升级。回滚应用版本时保留新增列和数据。

## 验证与限制

自动化测试覆盖旧记录、次数与重试、手动和新会话、修改停止规则、排队取消、归属与当前 turn 限定、原生终态和部署结算。浏览器测试覆盖参数边界、账号路由、Plan 禁止写入、命令互斥、控制到期、清理、中文输入、焦点、关闭与六语言资源。

固定 Playwright CLI 的真实本地 Chrome 会话验证了截图、坐标点击、中文输入和释放。Codex 浏览器中的模拟 API 页面验证了接管、输入、交还，以及 390px 窄屏无横向溢出。迁移与旧记录在独立 PostgreSQL schema 的事务中验证后完整回滚，未更新 UAT 业务表。

尚未验证真实模型对停止条件的判断、第三方网站登录、人机验证码及 UAT 中完整的人工接管流程。验证码仍由用户处理，不提供自动绕过。
