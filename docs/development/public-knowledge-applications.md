# 公共知识问答应用

新增第三种应用 `public_knowledge`。创建者选择已经导入目标网站资料的知识库，配置允许嵌入的网站和应用提示词，发布后将 iframe 放入该网站。知识内容来自创建者选定的网站资料，不固定使用 LinkSense 官网资料。本版复用现有知识库导入、解析和检索能力，不新增自动抓站调度。

## 功能和边界

- 普通、交互式应用继续使用原有执行链路；公共知识问答应用使用专用接口、数据表和运行环境，不建立匿名用户账号或普通应用安装记录。
- 每个应用共享一个 Worker 容器。每段访客对话绑定独立的原生 Codex 线程、HOME 和持久化目录。每轮运行结束即关闭该轮的原生进程；下一轮恢复对应线程。
- 创建者在页面配置最大同时回答数，范围为 1–20，默认 20；不超过上限的访客同时执行，超出的请求排队，空出名额后继续回答。全局执行名额和对话锁由 Redis 管理。BullMQ 持久化保存队列；等待名额的任务释放派发进程，不阻塞其他应用。执行完成后主动唤醒等待任务，不自动重放已经开始、失败或失去确认的原生轮次。全局最多同时执行 20 轮，待处理和正在处理的请求合计上限为 128，达到此保护上限才返回限流错误。
- 排队时在对应问题的答案位置显示加载动画及当前应用的等待人数，按仍有效且未取消的排队访客去重统计，包含当前访客；同一访客的多段对话不会重复计数。开始回答后移除排队提示，访客页不显示“正在回答”和“已回答”标签。
- 访客使用随机访问凭据，服务端只保存其摘要。浏览器按应用和嵌入网站分别保存访客会话，不发送已登录用户的令牌或 Cookie。
- 检索只使用发布版本选定的知识库，并复核创建者权限、文档状态和文档版本。原生工具、命令执行、跨对话记忆均关闭；模型网关同时移除工具声明。
- 创建和编辑表单在宽屏使用两列布局、窄屏使用单列布局。弹窗沿用普通应用的宽度、固定标题栏和固定底部操作栏，仅中间字段区域滚动；取消和提交按钮以相同尺寸靠右排列。支持选择已安装且启用的 Skill。Skill 仅提供文字指引，不执行脚本、浏览网页或调用工具；需要这些能力的 Skill 不适用于此类应用。
- 公共应用卡片通过右上角三点菜单分别提供编辑、启用/停用、问答日志、用量统计、网站嵌入和删除。编辑直接打开表单；日志与嵌入代码各有独立页面。删除沿用现有应用删除流程，关闭访问并保留问答记录。
- 用量统计支持按日期查看新增访客、新增会话、提问次数、各执行状态、已结束问答的完成率及已完成问答的平均耗时。统计来自公共问答记录，不计入普通应用对话；耗时从提问创建到完成，包含排队时间。当前未增加公共问答 Token 和费用计量。
- 所选 Skill 复用应用资源绑定及发布包快照。发布时仅固定 `SKILL.md`，不复制或逐轮读取脚本和其他包资源。回答前重新检查创建者权限、启用状态和快照完整性，把选中版本的指引放入该访客的独立目录，再通过 Codex 原生 Skill 输入加载。每个文件最多 128,000 字符，全部指引的序列化数据最多 512,000 字节。源包后续编辑不会更改已发布指引；停用或删除 Skill 会阻止继续使用它，需要创建者调整选择并重新发布。
- 创建者可查询本应用的访客对话、问题、回答、引用原文、模型、应用版本和耗时，并按关键词、日期和状态筛选。此入口不能读取其他创建者或原有普通应用的对话。
- 访客开始前看到记录与查看用途说明。默认访客凭据有效 24 小时、对话可查看 30 天。这些设置控制访问期限；本版未增加到期物理删除任务。
- 访客页提供中文、英语、西班牙语、巴西葡萄牙语、法语和日语。采用独立入口，无需登录，可取消回答、开始新对话和恢复当前访客的历史。
- 访客消息区、输入框和滚动行为复用普通聊天的 `ConversationThread`、`ConversationComposer`、`useConversationScroll`，仅适配公共问答记录。输入框采用纯文字模式，隐藏附件、语音和命令操作；公开回答禁用图片加载、内部资源链接及 HTML 预览。
- 访客聊天复用普通对话的实时过程、流式回答、展开/收起及用时展示。检索开始与结束由实际操作发布，模型的中间说明、可读摘要和答案增量通过原生事件持续更新；结束后保留过程记录，刷新仍可查看。用时继续采用服务端记录的总耗时，包含排队时间。参考资料开关同时控制正文引用角标和资料名称列表，不隐藏执行过程。
- 创建者可设置是否显示参考资料，默认开启。开启时正文引用复用普通聊天的灰色数字角标，点击定位到回答下方的资料名称；资料名称使用较小、较淡的文字，不展示引用原文。关闭时正文角标和资料列表一并隐藏，适用于流式回答、中间消息和历史回答；代码和普通 Markdown 链接中的数字保持原样。访客接口在开启时仅返回无原文的引用，关闭时不返回引用元数据。创建者问答日志保留完整引用原文，用于排查回答依据。
- iframe 沙箱使用 `allow-scripts allow-same-origin allow-forms`。`allow-forms` 使浏览器能触发共享输入框的提交事件，发送仍由页面脚本处理。更新前已复制的嵌入代码需要补充此权限；只刷新 iframe 内容不会改变外层页面的沙箱属性。

## 数据和部署

迁移 `20261105010000_public_knowledge_applications` 只扩展应用类型检查并新增四张专用表；`20261105011000_queue_public_knowledge_turns` 为这些新表补充派发状态和取消时间。两项均保留原有应用、账号、会话、消息及既有字段结构，没有删表、删字段或清空数据。

升级测试先应用变更前的迁移，写入普通应用、交互式应用和历史对话，再应用新增迁移，逐项验证原数据保持不变，并验证原应用目录仍能读取。公共应用禁止通过普通应用的修改、发布、分发和运行接口执行，避免误入原链路。

Skill 选择不增加数据库结构迁移。已有公共应用的设置未包含 `skill_ids` 时按未选 Skill 处理，仍可读取、编辑和继续问答；普通与交互式应用的 Skill 执行逻辑保持原状。

参考资料显示开关保存在既有设置 JSON 中，不新增数据库结构迁移。未设置该开关的公共应用默认显示资料名称；此前接近设置大小上限的应用仍能读取和保存。等待人数来自数据库中的排队状态，不修改执行调度或并发限制。

实时过程复用现有 `conversation_events` 持久化日志、Runner 事件 outbox、Redis 通知和 SSE 连接器，不新增数据库迁移。公共事件通过独立的应用/访客授权入口读写；普通会话仍沿用原有授权和执行路径。仅转发经过既有原生映射器及公共白名单处理的显示事件，隐藏原生线程标识、用户输入、引用上下文、原始推理及工具内容。事件重复投递按 delivery ID 去重，重连从事件游标恢复，不重放模型轮次。旧问答继续可读；此前未写入该事件日志的过程本次不自动补录，也不虚构缺失记录。

上线需要协调更新 Shared/API、Runner/Worker 镜像和 Web，并通过正式 Prisma migration 部署新增结构。Web 新增 `assets/public-knowledge-app.js`，继续使用既有嵌入样式文件；Nginx 为这个 iframe 单独保留 API 返回的网站嵌入策略。

开发验证仅对临时 PostgreSQL、Redis 和 Docker Worker 执行迁移和负载测试，没有修改现有业务数据库或部署服务。真实模型连通性、真实网站知识质量与目标生产机器容量仍需在部署环境验证。

## 验证入口

单元测试随各包现有 Vitest 命令运行。额外验证命令：

```sh
pnpm test:public-knowledge:postgres
CODEX_BIN=/path/to/pinned/codex pnpm test:public-knowledge:native
LINKSENSE_TEST_WORKER_BASE_IMAGE=linksense-runner-worker:oss-local pnpm benchmark:public-knowledge
```

原生和负载测试要求 Codex `0.154.0`。负载测试要求本地 Docker Unix socket，会构建并清理临时镜像、网络和容器，不读取项目 `.env`，不调用付费模型。可用 `LINKSENSE_LOAD_RESULT` 指定报告文件，用 `LINKSENSE_LOAD_INFERENCE_DELAY_MS` 设置模拟模型的处理时长。

资源结果及适用范围见 [真实并发测试报告](public-knowledge-benchmark-2026-11-05.md)。
