# LinkSense Mac 客户端 v1：云 Codex + 本机工具（文件 / 命令 / 桌面 / 浏览器）

本规格取代原“双模式桌面 Agent”的第一版范围。任务与 Codex 都在云端执行；桌面端
只做壳、云模式和本机工具执行器，不运行本地 Codex、本地模型或随包 Node/Codex 运行时。

## 1. 目标与已定决策

五个核心场景：

1. **任务执行**：云任务在云端 runner 上跑，桌面端与 Web 一致。
2. **本地文件系统**：云端 Codex 读写用户授权的本机文件夹。
3. **本机命令**：云端 Codex 在授权文件夹内运行终端命令，按会话权限模式在本机审批。
4. **Computer use**：云端 Codex 观察并操作本机桌面窗口。
5. **Browser use**：云端 Codex 通过本机 Chrome/Edge 扩展操作用户已登录的浏览器。

已定决策：

- 任务执行：**云端 Codex 编排**；不在本机跑 Codex。
- 文件写入：**会话级文件夹授权 + 只读/读写模式**——选择一次、逐条审计；未选择时
  默认使用本机 Home 目录。写/创建/删除是否需本机确认由权限模式决定。
- 本机命令：`local_shell_exec` + 四档权限模式（Auto / Manual / Accept edits /
  Bypass permissions），按会话保存在 Mac 上，默认 Manual；不提供 Plan 模式。
- 桌面动作：**内部 dev-proof 包全开；正式发布先安全子集**。
- 浏览器：**本机 Chrome/Edge 扩展**，不是云端 Chromium。
- 包：内部 ad hoc + dev-proof；正式发布需 Developer ID；移除随包 Node/Codex。
- 版本：内部构建解析 `agent-desktop` 最新稳定版并校验 checksums；发布包记录并固定
  实际验证过的版本。
- 旧代码：本地执行/M1b 代码停用保留，打包时不再带运行时。
- 设备注册：**登录即自动完成**；客户端启动时从应用数据目录的 0600 凭据文件恢复会话、
  幂等注册/续期设备并建立 WebSocket；UI 不出现配对码或“配对”动作。
- 产品语言：界面不出现“配对 / 设备 / Keychain / WebSocket”；只有“登录”和会话里的
  “本机文件夹 / 窗口 / 浏览器”。底层连接凭据自动签发、自动续期、自动撤销，用户无感。
- 设备身份仍是内部实现：稳定安装 ID + 账号 + 服务器 → 服务端设备行 + 本地凭据文件 +
  WS，用于路由、撤销和审计。用户只需在会话里选择文件夹和模式。
- 启动顺序：恢复本地凭据会话 → `ensure device`（同一安装 ID/账号/服务器幂等，轮换
  设备 token）→ 建立 WS。全程无用户动作。
- 切换账号先断开旧账号的设备通道，再为当前账号 `ensure device`；设备数量上限、
  重命名与审计保留。
- 旧配对码 UI 删除；服务端配对路由仅供夹具/其他客户端保留，后续可另行清理。

### 任务目标：只有云端

- 新任务一律在云端 runner 执行；UI 不提供 Run location，也没有默认运行位置设置。
- 移除：新任务 Run location、设置里的 Default run location、Continue on this Mac /
  Continue on the cloud computer、执行目标徽标。
- 设备/配对不再是执行目标，只用于本机工具（文件/桌面/浏览器）；设置页不提供本机工具
  配置，文件授权只在会话编辑器的文件夹按钮里选择。
- API 对新的 `execution_target=local` 创建请求返回明确不可用；保留历史字段和已有
  local 会话只读，不迁移、不重放、不新建本地回合。

## 2. 架构

```text
云端 runner（Codex app-server，任务在此执行）
  -> 工具组：local_files.* / local_shell.* / local_desktop.* / local_browser.*
  -> API 设备网关（账号、设备、任务、授权根、窗口/标签页授权、审计）
  -> 桌面设备 WebSocket
  -> 桌面桥（Go）
       -> 本机文件系统（授权文件夹）
       -> 本机命令执行器 + 本机审批（权限模式、进程组、输出/时长上限）
       -> agent-desktop（GUI 驱动）
       -> Chrome/Edge 扩展（本地浏览器）
```

- **一条共用 lane**：四个工具组都走现有设备通道与受限 tool.request/response，
  不各做一套。
- 云端模型只看到虚拟根 ID、窗口/标签页句柄和相对路径；看不到本机绝对路径、设备
  凭据或供应商密钥。
- 旧客户端不协商这些能力；云端 Codex 不暴露对应工具。

## 3. 本机文件

- 登录并启动即自动注册本机工具设备，不需要配对码或额外启用动作；会话编辑器的工具栏
  提供两个按钮：文件夹按钮打开本机选择器，旁边的权限（盾牌）按钮切换只读/读写。
- 不选择文件夹时会话默认使用本机 Home 目录（`~`），默认读写；选择过的文件夹按会话
  保存，同一文件夹再次选择时复用以授权记录。
- 模式为只读或读写，按会话独立保存；只读拒绝写/创建/删除，切换模式不需要重新授权。
- 输入 `@` 时列出当前授权文件夹的目录项（文件/子目录），选择后把相对路径插入消息；
  子目录可继续下钻。添加菜单不再承载文件夹授权，客户端也不显示附件“文件夹”项。
- 云端 Codex 工具：列目录、读、搜文本、写/改、创建、删除（删除进废纸篓）。
- 授权绑定账号、设备、会话和文件夹；服务端只路由当前会话的请求，桌面端再次校验
  会话对应的文件夹。
- 路径锁在授权文件夹内；拒绝 `..`、绝对路径、符号链接逃逸、跨根访问。
- 读有大小上限；二进制只返回元数据；搜索有结果上限并默认排除 `.git`、
  `node_modules` 等大目录。
- 写入前冲突检测（读取时的摘要/修改时间）；外部已改动则返回冲突，不覆盖。
- 审计保留相对路径、动作、结果、耗时；服务端只记操作与会话元数据，绝对路径不离开
  本机。
- 写入权限模式：Manual 时 write/create/delete 先在 Mac 上确认；Accept edits、Auto、
  Bypass 在授权文件夹内自动放行。只读授权仍然拒绝所有写入，与权限模式无关。

## 4. 本机命令与权限

- 云 Codex 通过 `local_shell_exec` 运行**非交互式**命令：一次调用一个 `zsh -c`
  进程，工作目录锁定在会话授权的本机文件夹内（`cwd` 为相对路径，省略表示文件夹
  根），路径逃逸、绝对路径和符号链接逃逸按文件工具同样的规则拒绝。
- 不新增“打开文件/URL/启动应用”工具：`open` / `open -a` 已由命令通道覆盖，单独
  工具只会扩大审批面。
- 四档权限模式与 Claude Code 一致，放在会话编辑器的盾牌菜单里，按会话保存在 Mac
  上，**默认 Manual**，没有 Plan：

  | 模式 | 终端命令 | 文件写入（write/create/delete） |
  | --- | --- | --- |
  | Manual | 每次本机确认 | 每次本机确认 |
  | Accept edits | 每次本机确认 | 授权文件夹内自动放行 |
  | Auto | 只读、单条、授权文件夹内的命令自动放行；其它确认 | 授权文件夹内自动放行 |
  | Bypass permissions | 不确认 | 不确认 |

- **Auto 的判定边界是确定性的本机判定，不调用模型**：整条命令必须同时满足
  1) 单条命令，不含任何 shell 组合、重定向、替换、引号或通配符（``; & | > < ` $ ( ) { }
     ' " * ? [ ]`` 等一律不放行）；2) 程序名在只读白名单内（`ls`、`cat`、`pwd`、
     `grep`、`rg`、`wc`、`git status/diff/log/show/...` 等）；3) 每个类路径参数经最近
     存在祖先解析后仍在授权文件夹内。`find -delete/-exec`、`git -C`、`--output`、
     绝对路径、`~`、`..` 和符号链接逃逸都会转为确认。判定不通过只是询问，不是拒绝。
- Auto 只判断命令行本身；在不可信的仓库里，仓库自己的 git 配置（例如
  `core.fsmonitor`）仍可能执行内容。Auto 适用于用户信任的文件夹；需要更强保证时用
  Manual。它不是沙箱。
- 审批在本机共享 Web UI 中显示：命令与相对工作目录，或文件操作的相对路径；只在本机
  渲染，不进入服务端。拒绝、45 秒未答复、页面不可用、Socket 断开或取消都**失败
  关闭**，命令不会执行。Bypass 仍需设备在线且任务正在运行。
- 命令以用户自己的 Mac 账户权限运行：文件夹授权约束的是工作目录与文件工具，不是
  OS 沙箱；审批与权限模式是运行任意命令的边界，界面与文档必须如实说明。
- 每个输出流上限 64 KiB（超出截断并标记），命令超时 1–120 秒（默认 30 秒），到时
  杀死整个进程组；退出码与部分输出返回模型，超时以 `timed_out` 标记。
- 审计只记录操作、会话、相对 `cwd`、结果、耗时和错误码；命令文本、输出、绝对路径
  不进入服务端审计或会话事件。
- 旧 Mac 不协商 `local_shell.exec`，云端不会向它暴露该工具；旧 API 忽略新增的
  操作字符串，旧 Mac 也不会收到该调用。

## 5. Computer use

`agent-desktop` 最新稳定版当前为 **v1.3.1**（2026-11-13），提供 61 个命令名、
57 个可执行命令。内部包开放完整用户动作集：

- 观察：`snapshot`、`find`、`get`、`is`、`screenshot`、`list-surfaces`
- 按 ref：`click`/`double-click`/`triple-click`/`right-click`、`type`、`set-value`、
  `clear`、`focus`、`select`、`toggle`、`check`/`uncheck`、`expand`/`collapse`、
  `scroll`/`scroll-to`
- 键鼠：`press`、`hover`、`drag`、`mouse-move`/`mouse-click`/`mouse-wheel`
- 应用/窗口：`launch`、`close-app`、`list-apps`/`list-windows`/`list-displays`、
  `focus-window`、`resize`/`move`/`minimize`/`maximize`/`restore`
- 剪贴板：`clipboard-get`/`set`/`clear`
- 等待：`wait`

不开放：`sandbox exec`（桌面引擎的沙箱命令不用于云任务；本机命令走独立的
`local_shell_exec` 与本机审批，见第 4 节）、`mcp`/`batch`（接口形态）、
`key-down/up`、`mouse-down/up`（引擎要求常驻 daemon，当前拒绝执行）。

约束与风险（内部包接受，发布前需解决或保持关闭）：

- `press/key` 在 v1.3.1 派发前只校验一次焦点，兄弟窗口抢焦点后不会复验。
- `scroll` 预检本身可能滚动页面。
- `launch` 需要应用白名单；`screenshot` 可能截到其他窗口且未绑定选中窗口身份。
- `clipboard` 读写系统剪贴板，涉及隐私。
- `drag` 需要窗口/坐标约束。
- 选中一个窗口、五分钟任务授权、暂停/恢复/停止、TCC（辅助功能/屏幕录制）、审计
  保留；内部 ad hoc 包每次重打包需重新授权。

正式发布子集：观察、点击、输入、只读等待；滚动在补充验证后开放；按键、拖拽、
启动应用、截图、剪贴板等引擎修复后再评估。

内部包使用 dev-proof（prepared hash）路径；正式发布仍要求 Developer ID 签名与
`--macos-release` 的 signer token。

## 6. Browser use

- 使用本机 Chrome/Edge 的 Manifest V3 扩展，复用已有配对、标签页授权、虚拟指针、
  截图浮窗和撤销。
- 云端 Codex 的 `local_browser.*` 工具经设备 lane 调用扩展；按标签页授权，撤销即时
  生效；截图限本回合读取，不进会话事件。
- 目标：扩展安装后通过账号自动连接，不引入新的配对码流程；如果浏览器要求一次
  明确授权，也只保留一次连接确认。扩展不可用时返回明确错误，任务可继续用其他工具。
- 不使用云端 Chromium 作为本机浏览器的替代；云端 `BrowserPanel` 保持现状。

## 7. 任务执行

- 云任务创建、SSE、文件/工件、知识库、连接器与 Web 一致。
- 云 Codex 只有在设备在线、任务已授权对应工具时才看到本机工具；离线时工具明确报错，
  任务保留草稿，不自动回落或重放。
- 不新增本地回合、本地 worker、本地模型代理或跨目标续接。

## 8. 包与版本

- 移除 `Contents/Resources/runtime` 下的 Node/Codex 运行时；保留 Go 壳、WebView、
  设备通道和 `agent-desktop` + helper（约数 MB）。
- 内部构建解析 `agent-desktop` 最新稳定 release，校验 `checksums.txt` 后打包，并
  记录实际版本；发布构建记录并固定已验证版本。
- 保留现有签名、公证、更新和诊断流程；更新与进行中云任务无互斥问题（没有本地回合）。

## 10. 验收

1. 云任务中 Codex 读到、搜到、改写本机授权文件夹；文件实际变化，冲突不覆盖。
2. 越界路径、符号链接、跨根、未授权文件夹、撤销后访问全部拒绝。
3. Manual 下云任务的命令在 Mac 触发审批；批准后执行并把输出返回模型；拒绝、
   45 秒未答复、设备离线或取消都不执行。Bypass 直接执行；Accept edits 在授权
   文件夹内自动放行编辑，命令仍需确认；Auto 只自动放行白名单只读命令。
4. 云任务中 Codex 选中一个本机窗口，完成观察、点击、输入、滚动等动作；暂停/停止
   生效；TCC 引导可用。
5. 云任务中 Codex 通过本机 Chrome/Edge 扩展操作已授权标签页；撤销后立即失败。
6. 设备离线时各类工具都返回明确错误；任务保留草稿，不重放。
7. 审计只含元数据与相对路径；服务端无绝对路径、文件内容、命令文本、命令输出、
   截图、键入文本或凭据。
8. 包内无 Node/Codex 运行时；内部包可完成以上场景，发布包只开安全子集。

## 11. 开放点

- 文件夹授权与权限模式按会话保存；未选择时默认 Home（`~`）与 Manual。是否需要
  “切回 This Mac”的显式动作。
- 删除已按文件写入规则处理（Manual 确认，其它模式放行）；是否需要始终单独批准。
- Auto 白名单是否需要扩充（例如 `jq`、`node --version`）或允许管道；当前一律确认。
- 截图是否进入模型输入（需要模型支持图像，且只限本回合）。
- 扩展配对的测试机分发方式（内部安装包/开发者模式加载）。
