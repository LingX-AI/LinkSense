# 同一用户的应用任务共享环境

## 运行边界

- 个人任务、应用草稿和独立副本继续使用用户个人 HOME、CODEX_HOME；项目决定工作目录。
- 已发布应用以“执行用户 + 应用 ID”确定环境。相同用户在同一应用内创建任务、分叉或使用新的发布版本，都复用 `users/<用户>/services/<应用>/home`，包括其中的 `.codex` 和 `workspace`。
- 不同用户、不同应用分别保存环境。嵌入访问使用服务端确认的执行身份；不同匿名身份不会仅因使用同一个应用而合并。
- 每个任务仍有自己的原生 thread、消息和任务控制记录。新建任务不复制 HOME、Python、Node 或插件安装目录。
- 公共依赖继续来自 Worker 镜像，用户安装的增量依赖保存在自己的环境内。

## 应用更新

任务执行时读取当前发布版本，任务记录中的 `application_version_id` 表示最近一次接纳的执行版本，不再用于选择旧版本。发布操作始终读取编辑中的草稿，避免再次发布旧版本内容。

应用更新不关闭正在运行的任务进程，不发送中断请求，也不重发用户消息。正在进行的原生调用自然结束；新任务和旧任务的下一次执行加载当前发布的插件、Skill、MCP 和应用配置。启动准备期间恰好发生再次发布时，已经接纳的启动继续使用其准备好的资源，下一次执行再读取最新发布。

复用 `proper-lockfile` 和已有的数据库启动意图：配置发布锁仅覆盖原生启动读取配置的阶段，不持有到整轮任务结束。旧任务的执行身份仍保留到终态确认；旧能力快照的清理在还有运行任务时暂缓。原生插件继续由 Codex 安装和验证，没有另外实现一套热更新协议。

交互式应用的页面包记录在接纳下一次执行时更新；执行中的事件校验仍使用当前任务已接纳的页面包。现有前端提交逻辑会刷新任务详情，并据此获取对应页面包。

运行器退出且旧能力配置已被替换时，可通过原生 `thread/read` 读取已完成、失败或中断的轮次，不恢复旧插件、不启动模型请求。无法确认终态或仍在继续的 Goal 保持恢复检查，不能推断为完成、额外启动一次或自动重放。

## 环境回收

复用[运行环境空间回收](runtime-storage-reclamation.md)中的删除许可。删除一个任务时，如果其他任务或分叉仍引用这个应用环境，只回收该任务的控制记录。最后一个引用被明确删除，且成果已保留、没有活动进程时，才允许回收整个应用环境。

完成、归档、令牌过期和容器空闲均不会删除 HOME。单纯创建更多个人任务或同一应用任务，只增加会话记录、任务元数据和实际生成的文件，不新增一整套环境。

## 历史目录归并

新代码不会在任务运行中搬动历史目录。提供独立运维命令，将原来的同用户、同应用的多个目录归并为一个目录；不新增数据库表或字段。

归并会修改任务工作目录引用、成果文件路径和清理记录的环境 ID，并保留原始目录及操作日志。历史原生会话数据库复用已有合并工具。旧工作文件放入 `workspace/imports/<原环境 ID>/`，避免同名文件相互覆盖；已登记文件的引用同步更新。凭证、用户安装内容或原生数据出现差异冲突时停止，不擅自选择或覆盖。

在运行迁移命令的环境中，设置可访问的 `DATABASE_URL` 和绝对路径 `LINKSENSE_USER_DATA_ROOT`。先等运行任务结束并停止接收新任务，再停止 API、Controller 和相关 Worker。该命令不会替你中断任何任务。

先验证完整归并，输出目录必须是新的目录，且位于用户数据根目录之外：

```sh
pnpm --filter @linksense/api runtime:convert-applications \
  --output-directory /absolute/path/application-check
```

确认检查通过、保存数据库备份后执行；Linux 部署需要以 root 运行，以恢复 API 与任务用户的文件所有权：

```sh
pnpm --filter @linksense/api runtime:convert-applications \
  --apply --workers-stopped \
  --database-backup /absolute/path/database.dump \
  --output-directory /absolute/path/application-conversion
```

成功后，`originals` 保留完整原始目录，不能把它与运行目录一起删除。验证旧任务能够继续、成果可下载、凭证和文件仍可用后，再另行决定备份保留时间。

若发生中断，启动检查会阻止 API 在未确认的目录状态下运行。保持服务停止，使用相同输出目录恢复：

```sh
pnpm --filter @linksense/api runtime:convert-applications \
  --recover --workers-stopped \
  --output-directory /absolute/path/application-conversion
```

恢复根据数据库实际提交状态决定保留归并结果还是恢复原目录。数据库状态混杂、目标缺失或日志不符时停止并保留启动标记，不猜测成功。

## 验证范围

单元测试覆盖应用环境复用、最新发布选择、发布并发、个人任务保护、运行中更新、启动锁释放、原生终态读取、删除引用保护及归并失败恢复。独立 PostgreSQL 测试验证历史数据、成果路径和外部访问凭证；Codex 0.154.0 离线原生测试验证共享 HOME、历史恢复、插件更新时在途 MCP 完成，以及进程崩溃后原生中断状态的读取。

本次实现未对本地正式数据执行归并，也未为应用更新重启正式服务。
