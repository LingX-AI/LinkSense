# 本地 Browser Use

云端浏览器保留现有执行实现。本地浏览器通过独立的 Chrome/Edge Manifest V3 扩展连接 LinkSense，不安装另一个本地 Agent，不修改用户浏览器的调试启动参数。

## 用户入口

在“设置 → 常规 → 浏览器扩展”下载安装包、解压，通过 Chrome/Edge 的开发者模式加载文件夹。刷新任意已登录的 LinkSense 页面后，会自动发起连接；首次在扩展弹窗确认可信的站点，可选择允许新建标签页。此后同一站点和账号自动连接、续接，不需要每次进入设置页。要使用已有页面，在该页面打开扩展并选择共享；停止共享和断开也在弹窗内操作。主动断开后，可直接在扩展点“重新连接”。

当前提供未打包扩展下载，尚未发布到扩展商店。扩展要求 Chrome/Edge 127+。LinkSense 连接地址须为 HTTPS，localhost/回环地址允许 HTTP；被操作的普通网页可以是 HTTP(S)。连接入口不支持跨源 API 部署。`LINKSENSE_PUBLIC_BASE_URL` 应与用户实际访问地址一致。

本地开发中，配置地址与页面地址仅在 `localhost`、`127.0.0.1`、`[::1]` 之间不同时，配对接口按请求 Origin 返回页面实际使用的主机名，协议和端口必须相同。正式域名不接受任意 Origin、Host 或转发头改写。配对码创建成功不代表已经连接，仍需在扩展弹窗确认并建立 WebSocket。

首版每个账号只有一个主动配对的浏览器，新的明确配对会替换旧连接。短时断线最多按 1/2/4/8/16/30 秒退避重连六次；恢复网络或重新聚焦 LinkSense 可继续连接，不重放浏览器操作。连接凭据与网页授权保存在 session storage，站点、账号、配对授权标识与新标签页偏好保存在扩展的 local storage；持久记录不含连接凭据。重启后打开已登录的 LinkSense 可自动续接，已有网页仍须重新授权。扩展只操作授权网页，不提供桌面应用控制、本机文件读取或上传传输。

## AI 的使用规则

- 普通公开网页、查资料与任务工作区预览继续使用云端 `linksense-browser`。
- 用户明确指定本地浏览器、已打开标签页或已有本地登录态时，使用 `linksense-local-browser` 和 Core MCP 的 `local_browser` 工具。
- 首先检查连接状态；未就绪时引导到 `/settings/general#browser-extension`，不自动把依赖本地状态的任务切换到云端。
- 同一个页面沿用其 tab ID；页面归属与浏览器分别记录，同一任务可使用两种浏览器，不增加必答的方式选择弹窗。
- Plan 模式仅允许 status、tabs、snapshot 和 screenshot；Runner 与 API 都检查此限制。

本地工具包含 status、tabs、open、navigate、snapshot、screenshot、click、click_at、type、scroll、key、release。页面快照使用 CDP Accessibility tree；点击引用包含 document loader ID 和 backend DOM node ID，导航后旧引用失效。截图返回独立 MCP image 和 CSS viewport 尺寸；坐标输入使用 CSS 像素。

## 连接与授权

Web 设置页只发送检测/配对请求。Content script 校验同窗口、同源和设置路径，不能接收页面发来的任意浏览器动作。扩展弹窗再次显示 LinkSense origin 并确认配对；长期连接凭据只进入扩展后台。

确认连接时绑定弹窗实际显示的 origin，待配对地址被其他页面替换时拒绝连接。配对和断开按用户最新操作串行处理；配对请求返回前断开不会重新建立连接。自动续接同时绑定站点与账号，服务端校验当前有效的配对授权标识；旧浏览器在关闭期间被撤销或被另一浏览器替换，也不能自动抢回连接。主动断开、撤销和更换账号保留明确授权步骤。弹窗监听连接与标签页状态，显示当前网页，并拒绝共享 LinkSense 自身和浏览器内部页。

后端配对码有效期两分钟且只能消费一次。连接凭据有效期一天，Redis 只保存凭据哈希和账号/认证版本关联。扩展通过 WSS 的第一条消息认证，不在 URL、日志或模型工具参数中传递凭据。连接、命令和结果通过 Redis 协调；API 进程只持有自己的 socket 和短期传输状态。

配对码交换接口 `POST /api/v1/local-browser/pair` 使用 `@fastify/rate-limit` 和现有 Redis，在校验请求体和消费配对码前按来源 IP 限制每分钟 10 次请求（IPv6 按 /64 网段聚合）。多 API 实例共享计数，Redis key 使用现有登录限流密钥进行 HMAC，不保存原始 IP；超限返回六语言 `LOCAL_BROWSER_PAIR_RATE_LIMITED`、HTTP 429 与 `Retry-After`，不消费配对码。Redis 不可用时拒绝交换。来源沿用 Fastify 的 `trustProxy` 配置，启用代理信任时应由可信入口清理客户端传入的转发头。既有凭据和配对授权格式不变，无需迁移或重新配对。

首次确认生成服务端配对授权标识，有效期为最后续接后 30 天；后续自动配对在 Redis 中原子核对该标识。撤销或新的明确配对使旧标识失效，不能仅凭已登录的 Web 页面恢复它。旧版凭据与连接记录没有此字段时仍可继续使用；更新扩展后首次确认会建立自动续接授权。

Runner 沿用既有 Core MCP → Worker → Controller → API 链路，绑定正在执行的 turn、任务及 owner。API 再校验用户状态、任务归属、运行状态和 Plan 限制。命令按账号串行、只投递一次，超时或不确定失败不自动重试。取消会清除未投递命令，并通知扩展拒绝尚可取消的协议步骤；已完成的网站操作无法撤回。

发布服务的外部会话不能继承发布者的本地浏览器和登录态；Controller 与 API 都拒绝带 service-session scope 的本地浏览器请求。设置页撤销连接会立即使当前命令失效。扩展在异步调试器连接前后重新检查授权、连接代次、取消和截止时间，并在取消或超时时解除调试连接，避免卡住后续命令。

扩展只列出用户授权的页面。首次操作将该 tab 归属当前任务，其他任务不能操作，直到 release 或用户重新授权。LinkSense 自身 origin、浏览器内部页和隐身页面拒绝控制。断开不关闭用户网页；失效引用要求重新观察，不猜测旧节点。

页面内容与截图按任务发送给 LinkSense 及配置的模型处理，不承诺所有数据仅在本机。原云端浏览器的命令、进程清理、面板和会话隔离不与此链路共享。

## 页面控制提示与虚拟鼠标

扩展 0.4.1 在正在读取或操作的授权标签页保留品牌描边与虚拟鼠标，不再显示网页顶部的 LinkSense / Page shared / Stop sharing 提示条。停止共享继续使用扩展弹窗中的入口。点击前会把蓝色虚拟指针移动到实际目标，页面收到同一组 CSS 视口坐标的原生 `mouseMoved` / `mousePressed` / `mouseReleased` 事件；等待指针到位后再点击。提示层不接收输入文字。指针位置不变时不重复移动；后台标签页或减少动态效果偏好下直接定位，避免等待屏外动画。

提示层使用独立 Shadow DOM 与手动 Popover，不改写网页布局。整个装饰层不接收点击，也不进入任务的无障碍快照。页面样式、根字号和变换不应改变指针坐标或提示尺寸；Tailwind 的 Shadow DOM 变量缺省值由构建时生成，不向网站全局注入 CSS。

在扩展弹窗停止共享、释放页面、断开或取消时会清除提示，并取消尚未完成的点击。移动期间发生文档切换会拒绝旧坐标。长时间没有更新会自动隐藏描边和指针。

扩展的 `scripting` 权限仅用于向已经授权的目标页按需载入固定的 `control.js`。普通网页不预载控制渲染代码；全局配对桥仍保持独立。提示层失效不会重放浏览器操作，原云端浏览器实现与 Codex turn 生命周期不受此界面影响。

## Browser Use 发现引导

设置页的安装步骤仅显示当前浏览器对应的 `chrome://extensions` 或 `edge://extensions`，下载、扩展管理、刷新与复制入口使用统一的前置图标。扩展 0.4.4 增加固定的 `open_extensions` 页面桥动作，由扩展在新标签页打开自身浏览器的扩展管理页，不接收目标 URL，不增加权限，也不暴露给 AI 浏览器工具。点击管理页入口始终优先请求直接打开，不依赖可能过期的初次检测结果；打开成功不读写剪贴板。后台仅接受顶层设置页，核对浏览器提供的当前来源 URL、非 opaque 的同源 origin 与当前账号的会话、待配对或信任站点。未安装扩展、旧版扩展或请求被拒绝时才退回复制对应地址，并提示粘贴到地址栏；普通网页无法直接导航到浏览器内部管理页，不能承诺无扩展时从网页一键打开内部设置。独立的“复制 LinkSense 地址”入口保留。

界面功能名称统一为 **Browser Use**，设置区、预览、执行状态、能力名称与扩展名称保持一致；工具名、Skill 标识和现有配对协议不变。

目前仅支持桌面版 Chrome / Edge。客户端优先读取低熵 User-Agent Client Hints 的品牌与移动端标识，缺失时使用 UA 回退；不请求高熵设备信息。Safari、Firefox、移动端及已识别的其他 Chromium 浏览器不检测扩展、不配对、不发起意图请求。设置页始终显示支持范围标识，不支持时提供 Chrome / Edge 官方下载链接与复制 LinkSense 地址的入口，引导用户换浏览器打开本站。此检测仅用于功能引导，不作为服务端权限判断。

普通可交互聊天复用全局扩展连接状态，无新增轮询。只有扩展未检测到或当前尚未连接、且引导未关闭时，才为最新一条已发送用户消息调用 `/conversations/:id/browser-use-intent`。该小请求只读取当前账号拥有的普通会话中最新用户消息，最多发送 2000 字符，复用管理员配置的标题模型与协议适配，明确要求仅返回 `true` / `false`；例如“google 搜搜看看 guygubaby”应返回 `true`。没有标题模型、超时或输出格式不符时静默返回 `false`，不创建 Codex turn、不使用工具、不修改任务生命周期。

意图请求使用低网络优先级，不阻塞输入、发送或主回复。客户端按账号、会话、消息 ID 缓存，禁用自动重试与聚焦重查；助手流式 token、组件重渲染和扩展轮询不重新调用。每条待判断消息先做一次按需扩展检查并更新共享状态，避免全局缓存仍显示离线时误调用模型；这不是新增轮询。Redis 按消息内容哈希去重并缓存布尔结果 24 小时，多 API 进程共享进行中标记；模型单次调用限时 5 秒且不重试。用量以 `browser_use_intent` 单独计量，并覆盖六语言统计名称。没有新增数据库字段或迁移；旧任务与旧用量仍可读取。新版共享契约、API 和 Web 需一同发布，避免旧客户端解析新用量分类失败。

识别为网页需求后，未检测到扩展时显示安装引导，已安装但未连接时显示连接引导；连接完成立即收起。空任务、未发送消息、只读、嵌入、应用运行和应用开发界面不显示此引导。

引导复用共享非模态 Popover，不抢走输入焦点。按 Escape 或点击外部只收起弹层，保留可重新展开的 Browser Use 入口，也不阻止下一条用户消息的意图检测。只有明确点击“暂不需要”或前往设置，才在本标签页当前账号的浏览器会话内停止提醒；没有可用 session storage 时，至少在当前聊天挂载期间保留该选择。旧版无法区分点击外部与主动拒绝的 `true` 标记不再抑制检测，升级后可能重新提示一次，新的明确关闭选择保存为 `explicit`；不影响任务、扩展配对或其他持久化设置。

入口指向 `/settings/general#browser-extension`，保留返回原聊天的路径，设置页在路由完成后将配置区滚动到可见位置并移入键盘焦点。仅由用户点击进入设置，引导本身不安装扩展、不发起配对、不代替用户授权，也不阻塞原有云端浏览器任务。原配对与自动连接链路保持现状，旧扩展仍可完成检测；更新 0.4.3 安装包后扩展名称显示为 LinkSense Browser Use。

## 会话截图浮窗

扩展 0.3.0 会在当前任务成功打开或操作已授权网页后生成小尺寸 JPEG 预览，最多保留最近八个任务的预览，存于扩展 session storage。首次打开或导航时，预览会短暂等待网页载入；预览失败不会把已完成的浏览器操作改成失败，也不会重放操作。

会话中的截图浮窗沿用对应 tab ID，点击可激活该标签页并聚焦所在浏览器窗口。读取和切换同时校验配对账号、LinkSense origin、当前会话路径、任务 ID 和页面授权；撤销共享后不再显示。预览通过同源扩展桥送回当前 LinkSense 页面，不另写入数据库或任务消息。

扩展 0.4.2 使用浏览器提供的 `chrome.tabs.get(sender.tab.id)` 读取当前会话路径。Chrome 的消息发送者 URL 在页内路由切换后可能仍保留文档初始路径，不能用它判断用户现在所在的会话；该问题已在真实 Chrome 的 `pushState` 回归中复现。来源文档 origin、当前标签页 origin、顶层 frame、配对账号、会话 ID 和目标页授权仍须同时通过检查；不信任页面自行传入的 URL，也不新增权限。API 行为参考 [Chrome Tabs](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-get) 与 [MessageSender](https://developer.chrome.com/docs/extensions/reference/api/runtime#type-MessageSender)。

浮窗使用现有 Motion 的 drag，支持拖动图片或顶部手柄；松手按会话内容区域吸附到最近的左上、右上、左下、右下角。该区域避开顶栏和输入框，视口或面板尺寸变化后重新约束位置。按方向键可移动到相应角落，位置按账号保存在本机。关闭浮窗只隐藏预览，不关闭或停止共享真实标签页。没有扩展或当前任务没有授权预览时，不显示浮窗。聊天页在前台时每 1.5 秒读取最新预览；首次扩展请求超时也会继续检测，扩展稍后可用时自动显示，不需要重新进入会话。后台暂停轮询，返回聊天时重新读取。

## 构建与部署

API 的 `dev`/`build` 会构建扩展到 `apps/api/dist/browser-extension`，设置页通过鉴权下载 ZIP。弹窗通过 Tailwind 构建并复用 Web 的语义主题，品牌图标从现有 SVG 生成 16/32/48/128 像素 PNG，用于工具栏、扩展管理页和弹窗。安装包附带所需许可证。可单独运行：

```sh
pnpm --filter @linksense/api build:browser-extension
```

API、Runner/Worker 和 Web 应作为同一版本发布。新增内置 Skill 已更新内容指纹，API 会为既有任务刷新 publication；Runner 继续严格校验发布内容。无需数据库迁移。不要将新版 API 的 Skill publication 与旧版 Worker 长期混用。

新增保留 Skill 名 `linksense-local-browser`。升级其他实例前需检查是否已有同名自定义能力；存在时须先解决命名冲突，不能直接发布后要求用户重建任务。本轮只读核对当前环境的 `capabilities.name`，同名记录为 0；没有修改历史资源。

开发源同步、应用构建指纹与 API 构建都包含扩展源码和构建脚本。Nginx 配置及 Vite 开发代理已包含 `/api/v1/local-browser/socket` 的 WebSocket upgrade；自定义外层代理也需要转发该路径，保持 Origin 和长连接。
