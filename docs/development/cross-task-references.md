# 跨任务引用

在普通聊天输入框输入 `@`，继续输入任务名称筛选，用方向键选择、Enter 确认，或点击候选。Esc 取消并保留原文字；邮箱和 URL 中的 `@` 不触发。也可使用「添加 → 引用其他任务」多选面板，切换归档任务和加载更多结果。

每条消息最多选择三个本人普通任务。选中后显示可移除标签，光标保留在输入框；引用随草稿保存，发送失败会恢复。发送后的消息显示来源链接。旁聊、应用托管会话和 Goal 提交保持原有交互；运行中带引用的新消息排队，不注入当前执行。

## 授权与读取

客户端只提交所选任务 ID。API 校验来源归属和类型，并保存可信消息展示元数据；排队请求另有内部选择事件，启动时再次校验。粘贴任务 ID 或伪造提示正文不会获得读取权限。

内置 `read_referenced_conversation` MCP 工具由 Runner 绑定当前活动任务和执行轮次。每次读取都检查本轮明确选择的来源、账号和来源归属，拒绝读取其他账号、应用托管会话和旁聊。来源删除或原生线程变化时拒绝返回结果。

工具只返回来源当前原生线程可见的用户与助手文本，过滤内部选择封装和被替代的计划消息；不开放附件、工具日志或隐藏推理，不修改来源任务。每页最多 20 条、共 16000 字符，以游标和偏移续读，支持既有超长消息。

## 兼容性与验证

不新增数据库表或必填字段，旧消息、旧草稿和普通发送请求继续可用。复用现有消息元数据和原生 Codex 执行链路，不新增整轮重试。升级时先部署 API 和 Runner，再部署 Web；已有用户运行环境会在下次配置内置 MCP 时刷新环境变量列表，无需重建任务。

测试覆盖来源授权、输入边界、续读、排队与 steer 限制、草稿恢复、鼠标与键盘选择、焦点、乐观展示和六语言资源。真实模型工具调用及浏览器视觉端到端流程尚未实测。
