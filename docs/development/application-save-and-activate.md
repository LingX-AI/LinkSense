# 应用保存与生效

## 交互规则

- 普通应用创建、交互式应用导入、应用编辑、应用包更新的按钮分别为“创建”“导入”“保存”“更新”。成功后自动保存发布记录并对创建者生效。
- 编辑默认保留已有版本号；没有版本号时使用 `0.0.1`。`v` 为固定展示前缀。编辑和更新应用包可使用相同或更高的 `x.x.x` 版本，不能降低版本。
- 开发面板独立的“发布”操作继续保留发布确认及建议升级版本。
- 当前用户的同一正式应用有任务运行或正在启动时，服务端阻止保存和更新，并提示停止任务或等待完成。检查与修改通过同一运行环境门控串行化，不能仅依赖前端按钮禁用。开发调试环境独立。
- 组织共享和应用中心保留原先提交的版本。创建者另行共享或上架后，接收者仍需手动安装更新。

## 数据一致性

应用包 UUID 和发布记录 UUID 标识不可变内容，显示版本号可以重复。内部发布序号继续递增，安装更新按发布记录判定，因此相同版本号也能提示更新。相同 ZIP 再次保存也必须处理本次资源选择，不得只按压缩包摘要跳过更新。

应用信息、包、资源绑定、发布记录和创建者安装在事务中切换。失败不应保存部分信息。卡片和详情读取相同的已安装发布记录。

## 数据库升级

迁移 `20260918150000_allow_repeated_interactive_package_versions` 仅移除交互式应用包的 `(application_id, version)` 唯一索引。保留所有历史包、发布记录、资产及字段；包主键及其他索引不变。已获得保留历史数据并采用增量迁移的确认。

部署新 API 前执行 `pnpm db:migrate:deploy`。未执行该迁移时，相同版本号更新仍会被数据库拒绝。已有重复版本号后不能直接恢复旧唯一索引，不得通过删除历史包来回退；应采用前向修复。

验证包含旧约束下的历史数据、增量迁移后的历史保留、同版本号包更新、正式任务阻止修改、卡片与详情一致、实际页面资源切换及共享接收者手动安装。
