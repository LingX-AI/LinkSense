# LinkSense for Open WebUI 需求规格

| 项目 | 内容 |
| --- | --- |
| 文档版本 | 1.0 |
| 编写日期 | 2026-10-14 |
| 产品名称 | LinkSense for Open WebUI |
| 状态 | 产品范围已确认；接口设计和完整集成验证尚未完成 |
| 阅读对象 | 产品、LinkSense 开发、插件开发、测试和部署维护人员 |
| 首个验证基线 | Open WebUI 官方 v0.12.0，提交 `15818d88fd7bde1b73de33590f50d15d21e8d7c1` |
| 当前交付范围 | 需求规格，不代表功能已经实现或允许执行数据库迁移 |

用户在官方 Open WebUI 中选择 LinkSense 后，由 LinkSense 在后端执行任务，并在原对话中返回进度、补充问题、正文和文件。用户无需另行登录 LinkSense，也无需离开 Open WebUI 完成常规任务操作。

**不可妥协的前提是：Open WebUI 保持官方实现，由 LinkSense 和配套插件适配它。不得以修改 Open WebUI 源码、替换原文件或运行时打补丁的方式满足任何功能要求。**

## 1 目标与范围

### 1.1 产品目标

提供完整的任务执行入口，而非跳转链接或让聊天模型偶尔调用的工具。用户明确选择 LinkSense，即明确委托 LinkSense 完成任务；不再由 Open WebUI 当前聊天模型判断是否委托，也不由另一个模型重新组织 LinkSense 的最终结果。

核心验收场景：用户只登录 Open WebUI，上传 Excel 并选择 LinkSense，要求分析数据和生成 PPT；用户在原对话中查看进度、回答补充问题、预览或下载 PPT，随后要求修改第三页并导出 PDF。后续轮次延续同一任务及其文件，任务归属于正确的 LinkSense 用户。

### 1.2 必须交付的范围

- 输入框中的原生 LinkSense 选择入口及请求路由。
- 可信用户身份传递、按邮箱首次匹配、自动创建普通用户和持续绑定。
- 文本与附件提交、多轮对话、编辑、重新生成和分支关联。
- 流式正文、执行进度、待处理问题、结果与文件在原聊天中的展示。
- 停止任务、重复提交防护、断线恢复、后端重启后的状态核对与恢复。
- 用户和资源隔离、账号状态检查、额度控制、审计和错误处理。
- 原生插件安装、配置、升级、停用与卸载说明，明确支持版本和验收记录。

### 1.3 不要求完整复制的界面与能力

不要求复制 LinkSense 的完整工作台、终端、文件树、管理后台或编辑器；不要求在 Open WebUI 中编辑 Office 文件。文件修改通过后续对话完成，文件预览使用 Open WebUI 已支持的能力。

首版执行模型和能力授权由 LinkSense 管理，不要求将 Open WebUI 的模型密钥、工具库、知识库、记忆库和管理权限自动同步到 LinkSense。用户显式发送的聊天上下文、文件和引用材料属于输入，必须与自动迁移整个平台资源区分。

语音通话、自动化任务、多人共同操作同一任务以及其他聊天客户端的适配不是本次交付目标。集成必须能识别不支持的调用场景并明确拒绝，不能在共享聊天或自动化请求中错误继承他人身份。

## 2 最高优先级约束

### R01 保持 Open WebUI 官方实现

下列要求高于任何功能、进度或性能目标，违反任意一项即不可验收。

| 边界 | 允许 | 禁止 |
| --- | --- | --- |
| 部署 | 官方发布包、官方镜像或未修改的官方源码构建；官方支持的配置 | 必须部署 LinkSense 维护的 Open WebUI 分支或改造镜像 |
| 扩展 | 管理界面安装原生 Functions 等插件；使用官方插件契约和现有 API | 修改 Open WebUI 前后端源码、替换原文件、猴子补丁或拦截改写核心函数 |
| 界面 | 原生 Filter、Pipe、Action 和事件提供的界面能力 | 浏览器扩展、用户脚本、DOM 注入、代理注入脚本以补造界面 |
| 数据 | 通过有权限校验的 Open WebUI API 或插件文档支持的服务接口操作 | 修改 Open WebUI 数据库结构、直接改库绕过服务规则和授权 |
| LinkSense | 新增集成模块、必要的页面和配置、接口、持久化关联 | 用修改宿主的方式转移应由 LinkSense 承担的适配工作 |

插件可以调用文档明确支持的宿主接口，但必须固定适配版本并测试。能够在 Python 中导入某个内部对象，不等于该对象是稳定扩展契约。不得以未公开私有对象、未记录行为或反射修改宿主作为最终方案的必要条件。

能力不足时，应记录具体阻断场景、证据和符合约束的候选办法。不能私自删去需求、改成站外操作，或以“临时方案”为由突破本约束。必要的产品范围调整须得到维护者明确确认。

## 3 角色与责任

| 角色或系统 | 责任 |
| --- | --- |
| Open WebUI 用户 | 登录、选择执行入口、提交内容、回答问题、停止任务、查看结果 |
| Open WebUI 管理员 | 安装和启用插件，设置可用范围、LinkSense 地址和服务凭证 |
| LinkSense 管理员 | 授权可信宿主，配置自动开通、默认额度和能力，管理撤销与审计 |
| Open WebUI | 保持原有登录、聊天界面、消息存储、附件服务和插件执行机制 |
| LinkSense 插件 | 转换宿主身份与请求，关联消息，传递控制操作，映射事件与附件 |
| LinkSense 集成模块 | 校验来源和身份，维护关联与同步状态，复用任务服务并校验资源权限 |
| LinkSense 原有执行系统 | 管理任务执行、工作目录、工具、文件、原生中断与恢复语义 |

配套插件采用宿主所要求的 Python 接口；LinkSense 侧继续采用项目现有 Node.js、TypeScript、Fastify、Zod、Prisma、Redis 等技术。不得仅为协议转接新增另一套任务引擎。新增依赖前检查现有依赖、文档和类型，并评估维护状态与许可。

## 4 官方能力与证据边界

验证日期为 2026-10-14，基线为官方 v0.12.0。此次能力检查执行了 19 项原始后端函数隔离测试，数据库和网络边界使用替身；未启动完整 Open WebUI、未完成浏览器端到端验证，也未连接真实 LinkSense 执行任务。这些结果用于技术选型，不能作为产品验收结果。

| 能力 | 已有证据 | 尚需完成的验证 |
| --- | --- | --- |
| 输入框可切换 Filter | 官方文档和前端源码存在原生选择入口 | 正式插件安装、可见权限和操作体验 |
| Filter 路由到 Pipe | 选中后修改目标可进入真实 Pipe 分发函数；未选中保留原目标；目标权限检查仍执行 | 完整中间件、不同模型配置、工具和知识处理的相互影响 |
| 用户与消息信息 | Pipe 可获得用户邮箱、用户 ID、聊天 ID、消息 ID、父消息和内部任务类型 | 可信身份交换、伪造拒绝、自动创建并发冲突 |
| 进度和附件持久化 | `status`、`files` 可触发存储写入 | 真实数据库、浏览器刷新和并发同步 |
| 附件事件别名 | `chat:message:files` 在本次基线不会执行同样的存储写入 | 发布插件固定使用已验证的持久化方式 |
| 附件去重 | 重复 `files` 事件会累积重复附件 | 插件与 LinkSense 联合去重、崩溃窗口恢复 |
| 输入附件处理 | Filter 的 `file_handler` 路径会删除标准附件字段；事先保留的独立引用可继续传入 Pipe | 不误用内置 RAG、不丢附件的完整提交 |
| 原生文件预览 | 消息附件与文件弹窗源码包含图片、PDF、Excel/CSV、DOCX、PPTX 处理 | 真实文件、权限、下载、布局和失败提示 |
| 普通刷新恢复 | 活跃任务的正文快照可叠加到聊天记录；进度和附件可保存 | 真浏览器断线、刷新、多标签页与事件竞态 |
| 后端任务丢失 | 任务登记丢失后，原生读取不会自动重建 Pipe 执行 | 无重放的任务核对和连接恢复方案 |
| 停止 | 等待上游时取消能进入 Pipe；在两次输出之间取消，不保证传入 Pipe 的 `CancelledError` | 可靠取消收尾和远端最终状态确认 |
| 确认与输入 | 原生交互可调用；旧会话断开、其他用户会话和超时会返回错误 | 刷新后的待处理请求恢复和准确应答 |

输入框 Filter 的选择在此基线使用浏览器会话存储，不能据此宣称跨设备持久选中。正式产品需准确展示当前选择；任务关联本身必须持久化。出处见第 20 节。

## 5 用户入口与执行接管

### R02 选择与路由

1. 用户能从输入框的原生集成入口启用 LinkSense，选中状态清晰可辨。
2. 选中后，正常用户提交确定性地进入 LinkSense，不依赖其他模型发起工具调用。
3. 未选中时，插件不创建账号、任务或上传副本，不影响原有聊天流程。
4. 选择变化从下一次提交生效；关闭选择不自动中断已经受理的任务。
5. 任务运行时产生的进度和结果仍回到其原消息，不因当前选择或聊天分支改变而写到另一条消息。
6. LinkSense 不可用或权限不足时，明确失败，不静默改由普通模型执行，也不把失败包装成正常回答。
7. 自动标题、标签、后续问题、查询生成等宿主内部请求不得创建执行任务。插件应区分请求用途，使用不会触发实际执行的宿主配置或处理路径。
8. 不支持的临时聊天、多模型同时回复、共享协作聊天等场景，必须在产生任务或账户副作用前识别并明确提示。正式支持这些场景必须补齐独立身份、幂等和归属测试。

现阶段技术候选为“可切换 Filter 加 Pipe”。Filter 只负责入口路由及必要的请求整理，Pipe 负责转接。Filter 修改目标后，宿主仍可能执行原模型的部分预处理；必须实测并通过插件和配置避免重复执行工具、附件丢失、历史重复注入和指令污染。

跨设备自动保持选中不是已验证能力。没有原生支持时，用户重新启用 LinkSense 后必须能延续任务；不得通过改造宿主存储或界面伪造选择持久化。

## 6 身份与权限

### R03 可信识别与自动开通

LinkSense 必须区分服务调用方身份与实际执行用户身份。认证插件来自某个可信 Open WebUI，不代表任意邮箱都可自动绑定到已有账户。

首次使用流程如下：

1. 校验已登记宿主、服务凭证或签名、有效期、请求用途与防重放信息。
2. 从可信宿主服务端取得用户标识、邮箱、显示名称和语言，只接收必要字段。
3. 按“宿主实例标识加外部用户 ID”查询现有绑定。
4. 没有绑定时，对符合信任策略的邮箱使用项目统一规则规范化并查找 LinkSense 账户；不得自行折叠邮箱别名、删除 `+` 后缀或改变邮箱服务商语义。
5. 存在且可用时建立绑定；不存在时自动创建普通用户，应用预先配置的用户组、额度和能力策略，并建立绑定。
6. 用户创建与绑定必须保证并发唯一性、事务一致性和审计，重试不得创建多个账户。

“可信邮箱”必须来自经验证的身份来源或管理员明确授权的受控账号目录。当前 Pipe 的用户信息包含邮箱，不等于其中存在可直接采用的邮箱验证证明。正式设计必须说明如何建立这种信任；来源不满足策略时不得自动合并已有账户。

已经绑定后以稳定外部用户 ID 为准。邮箱变更不得自动改绑到另一个账户；邮箱与既有绑定冲突时中止敏感操作并交由管理员处理。多个宿主必须独立登记，不能仅凭相同外部用户 ID 共享身份。

当前 LinkSense 外部登录会为不存在的用户创建禁用账户。此次需求要求可信集成中新建普通用户可直接执行，必须新增独立的自动开通策略，不能全局取消现有外部登录审批或启用公共注册。现有禁用账户始终保持禁用；不能通过首次绑定重新激活。

### R04 授权与隔离

- 任务、上传、事件、问答、中断、分支和文件下载均在 LinkSense 服务端验证实际用户与资源归属。
- Open WebUI 的管理员角色不得直接转换成 LinkSense 管理员；集成凭证不授予任意管理权限。
- 已有账户按既有权限和额度执行；自动创建用户使用普通用户策略，无默认密码或共享管理员会话。
- 账号禁用、集成撤销、额度不足和能力权限变化必须在操作边界重新检查，不能只在首次绑定时校验。
- 单个用户只能查看和操作自己的关联任务。共享聊天内容不构成获取他人 LinkSense 凭据或工作目录的授权。
- 服务凭证与委托用户凭证不得写入浏览器正文、附件 URL、查询参数、日志或模型提示词。
- 身份验证失败应拒绝请求，不得用默认用户、系统管理员或另一条会话代替。

## 7 任务提交与多轮语义

### R05 受理与幂等

集成接收正文、必要历史、附件引用和外部消息标识后，应先通过鉴权、附件检查和幂等检查，再调用 LinkSense 现有任务服务。受理回执必须包含可用于查询的稳定操作标识；执行轮次尚未创建时，仍应能够查询和请求停止该操作。

同一提交的网络重试必须返回原受理结果，不创建额外轮次或重复扣费。幂等范围至少覆盖宿主、实际用户、外部聊天、外部回复消息和操作类型。相同幂等标识但正文或附件不同，应报告冲突，不能复用不匹配的结果。

用户明确重新生成、编辑后重新提交与网络重试必须区分。若宿主没有提供足够信息，设计阶段须找出可验证的原生标识或拒绝歧义请求，不能仅比较文本是否相同。

同一任务的并发提交复用现有调度规则。选择排队、运行中补充还是拒绝忙碌请求，必须与 LinkSense 当前能力一致并向用户说明；不得并发修改同一工作目录。首版不把运行中输入自动解释为新任务或用户确认。

### R06 多轮上下文

- 首次接管当前分支时传入必要历史、当前输入及可访问附件；历史是任务背景，不能重放其中已经发生的操作。
- 后续轮次提交新增输入，沿用已有任务和文件，不反复向上下文追加全部历史。
- 在 LinkSense 关闭期间由普通模型新增的对话，重新接管时按实际消息链补入背景，不假定 LinkSense 已知。
- 新聊天具有独立关联。多标签页、同一用户多个聊天、插件重启不能导致串话。
- 长上下文使用既有模型与原生压缩机制；不得静默截断当前请求或关键附件，也不得引入自定义完整任务重试。
- 关联应保存在服务端持久化存储，不能以 Pipe 实例变量、进程内字典或浏览器会话作为唯一事实来源。

### R07 编辑与分支

消息编辑、重新生成、分叉与复制必须按宿主真实消息树处理。不要仅使用一个 `chat_id` 映射到唯一且不可分叉的执行上下文。

分支必须同时考虑文本历史和文件状态：从旧消息开始的新分支，不能继承原分支在该位置之后产生的文件修改。切换查看旧分支不应产生任何新执行；只有明确的新提交才可启动轮次。

复制聊天时，新的聊天 ID 与来源必须重新关联并校验权限。跨用户复制不得复制来源用户的凭据、私有目录或不可访问文件。

开发前验证当前项目固定 Codex 版本及 LinkSense 现有 fork、regenerate 对消息和工作目录的真实行为。若无法提供正确的历史文件状态，应把该具体分支操作列为发布阻断，提出满足官方扩展约束的设计并取得明确决策；不能只复制聊天文本冒充完整分支支持。

## 8 过程展示与用户交互

### R08 正文与事件

任务过程使用用户能理解的状态说明，例如“正在读取文件”“正在分析数据”“正在生成演示文稿”。不得展示原始 Codex JSON-RPC、内部路径、密钥、模型原始推理或完整工具参数与响应。

正文通过 Pipe 的流式输出机制返回；进度和附件使用已验证的原生事件。LinkSense 内部已执行的工具只能作为经过筛选的展示信息，不能作为待执行的 `tool_calls` 返回给 Open WebUI，防止宿主再次执行。

每个事件必须有稳定标识、所属操作、顺序与展示用途。同步程序按事件 ID 去重，按游标续读，正确处理迟到、乱序和终态后的产物到达。完成状态到达不等于所有文件已经同步完成，应分别记录执行完成和交付进度。

进度、最终正文、附件和可恢复的问题应能在普通聊天重新打开后查看。发布前必须验证真实数据库写入和浏览器重载，不能只检查 WebSocket 收到事件。`files` 重放需要去重；不能把仅实时展示的别名当作持久化接口。

### R09 提问与确认

待处理请求至少包含请求 ID、所属任务和轮次、类型、用户可见问题、允许的回答、状态和必要的期限。由 LinkSense 持久保存，Open WebUI 弹窗或消息只是交互呈现。

- 简单问题和确认优先复用原生接口；若原生界面不足，采用允许的插件交互，不能跳转到 LinkSense 网站才能继续。
- 用户回答必须对应明确请求，不能按“最近一个问题”猜测；重复答复保持幂等，失效或已完成请求不能再次推进执行。
- 超时、关闭弹窗、浏览器断开或返回错误对象不代表同意。状态应保持等待、按原有规则过期或明确取消。
- 页面刷新后能够识别待处理请求，并在当前聊天内重新展示或通过明确的原生插件操作恢复应答。
- 新的一轮自然语言消息不能自动当成批准。若允许用聊天回答问题，必须有明确的关联和歧义处理规则。
- 多标签页同时回答时，只受理有效的一次；用户身份变化后重新鉴权。

## 9 文件闭环

### R10 输入文件与产物

Open WebUI 文件 ID 与 LinkSense 文件 ID 属于不同系统，必须建立关联，不能直接互换。文件字节传递、元数据、授权和生命周期均属于此次范围。

| 阶段 | 必须行为 |
| --- | --- |
| 输入 | 以当前用户权限读取选中附件；校验名称、类型、大小和数量；传入正确任务；失败时不得假装已读取 |
| 图片 | 同时处理消息内容中的图片与标准附件列表，避免只读 `__files__` 丢失图片输入 |
| 历史附件 | 只携带当前分支有权引用的文件，重复提交不重复导入相同版本 |
| 输出 | 选择最终或用户要求的产物，注册为可访问的 Open WebUI 附件；不自动公开工作目录和临时文件 |
| 预览 | 对支持格式进入原生预览，失败时显示可理解提示并提供有效下载 |
| 多轮修改 | 同一产物的不同版本可区分；不能覆盖历史附件的内容却保留旧名称和旧版本身份 |
| 历史访问 | 重新打开聊天后仍可按保留策略访问，不能只依赖一次性的短期链接 |

推荐将最终产物同步为实际用户所有的 Open WebUI 文件，并保存与 LinkSense 产物版本的关联。该方案是设计候选，需验证官方上传接口、用户授权和无需额外模型处理的路径；不得为省事把所有产物挂在共享管理员名下。

至少使用图片、PDF、XLSX、CSV、DOCX 和 PPTX 样本验收。原生预览不承诺 Office 编辑、宏运行或所有复杂版式完全还原。压缩包等未支持预览的合法产物提供下载，不伪装成支持在线预览。

上传和下载应支持流式传输、边界限制和明确超时。失败重试须基于文件版本、校验值和目标关联去重。限制值复用两端既有策略，以较严格者为准；冲突应提前提示。

临时文件清理、源产物保留、宿主副本保留及删除传播必须分别定义。默认不因宿主聊天删除、插件停用或卸载而硬删除 LinkSense 任务及源文件；停止向不存在或已撤权的目标聊天发送结果。任何新增自动删除策略另行确认数据影响。

## 10 停止与恢复

### R11 明确停止

用户点击原生停止按钮后，集成必须将停止意图准确传递给对应 LinkSense 操作。排队、准备、运行、等待用户和结果同步等阶段分别处理，不得误停同用户其他任务。

“请求已受理”与“实际已停止”分开呈现。只有 LinkSense 的真实终态确认后才能展示已停止。停止传递失败时应显示尚未确认的状态，并允许在当前聊天内进行确定性的控制或查询。

不能仅依赖 Pipe 内 `CancelledError`。必须验证取消发生在等待网络、解析响应、发送事件、持久化和两次输出之间等时机。正常完成与停止竞态以真实执行结果为准，不将已完成任务改写为已停止。

浏览器刷新、切换页面和网络断开不表达停止意图。Open WebUI 服务关闭也不能无条件解释为用户停止。重启后的状态核对不得创建新执行，自动重试仅限幂等控制和传输，不得重放完整任务。

### R12 连接恢复与状态核对

| 故障场景 | 必须达到的行为 |
| --- | --- |
| 浏览器刷新 | 读取已经保存的内容和附件，核对当前任务；仍在执行时继续显示后续事件 |
| 浏览器断网后恢复 | 从已确认游标恢复同步，不重复提交输入，不重复附加正文或文件 |
| Pipe 与 LinkSense 网络中断 | 有界重连，查询原操作和事件游标，显示连接状态；不创建替代任务 |
| Open WebUI 重启 | 识别原关联任务及其结果，在原聊天中提供可用的状态核对与恢复；不把任务丢失误报为完成 |
| LinkSense API 重启 | 从持久数据恢复关联、提交回执和同步游标；执行是否继续由既有运行时事实决定 |
| 用户等待确认时刷新 | 保留待处理请求，在当前聊天恢复问题与应答，不自动批准 |
| 多实例同时恢复 | 通过共享协调和幂等处理防止重复投递、重复上传和重复执行 |
| 目标消息或聊天被删除 | 停止向目标写入，不创建替代聊天冒充原消息；按既有任务策略核对远端任务 |

浏览器刷新后的恢复与进程重启后的恢复必须分开验收。后一种不由基本 Filter 加 Pipe 自动提供。

自动恢复的具体触发方式尚未确定，候选只能使用官方插件、API 和配置。如果只能提供用户在原聊天中点击原生插件操作恢复，必须明确说明其与自动恢复的差别，获得产品确认后才能作为验收方式。未经确认，不能将“用户重新发送原需求”作为恢复步骤。

## 11 状态与同步契约

### R13 执行事实与展示状态

以下是对外展示语义，不是要求创建新的 Codex 执行状态机。必须映射自 LinkSense 现有受理、队列、轮次、待处理请求和终态事实。

| 展示语义 | 事实依据 | 不得混淆 |
| --- | --- | --- |
| 已接收 | 已持久保存受理回执 | 不等于轮次已运行 |
| 排队或准备中 | 既有启动意图和调度状态 | 不能虚构进度百分比 |
| 执行中 | 实际轮次运行 | 不能由连接存活推断 |
| 等待用户 | 存在有效待处理请求 | 不等于任务完成 |
| 停止请求处理中 | 已记录中断意图，尚无确认终态 | 不等于已停止 |
| 已完成 | 执行系统确认完成 | 文件可能仍在同步 |
| 已失败 | 执行系统确认失败或受理失败 | 网络短时断开不等于执行失败 |
| 已停止 | 实际中断或执行前取消已确认 | 宿主停止输出不等于远端停止 |

同步状态应独立表达“连接中、连接中断、补齐事件、文件同步中、同步完成、需要用户处理”。同步失败不能改写执行终态。事件必须包含状态版本或顺序信息，晚到快照不得覆盖更新状态。

正式接口要区分待处理请求类型和有效范围，不能复用一个含义模糊的 `done` 字段表达执行、进度动画、文件交付和确认状态。

## 12 逻辑架构与接口边界

逻辑调用路径：

```text
Open WebUI 输入框的原生 LinkSense 选择项
  → Filter 进行入口路由和必要的请求整理
  → Pipe 转接身份、消息、附件及控制操作
  → LinkSense 集成模块校验并维护关联
  → LinkSense 既有任务服务与执行系统
  → 脱敏事件和产物经适配返回原聊天
```

Filter 和 Pipe 属于正式交付插件；是否增加原生 Action 或 Event Function，必须依据停止、恢复原型的结果决定。不得为了维持上图的形式而把缺失能力隐藏在宿主补丁中。

### 12.1 LinkSense 集成模块应提供的操作

下表定义职责，不表示这些集成端点已经存在，也不冻结最终 URL。实现可组合操作以减少往返，但不能省略授权与幂等边界。

| 操作 | 主要输入 | 主要输出与限制 |
| --- | --- | --- |
| 身份识别与委托 | 宿主认证、可信外部身份、用途 | 作用域受限的执行身份；不得返回管理员登录会话 |
| 获取或创建聊天关联 | 外部聊天、用户、上下文基点 | 关联 ID、LinkSense 任务标识、上下文基点 |
| 导入附件 | 用户归属、宿主文件标识、内容和校验值 | LinkSense 文件关联与版本；传输结果可重试查询 |
| 提交轮次 | 操作身份、父消息、新输入、附件、幂等键 | 受理操作 ID、已有或待创建的轮次 ID、状态 |
| 读取快照 | 用户身份、关联或操作 ID | 执行状态、待处理请求、产物、同步游标 |
| 订阅或补读事件 | 操作范围、上次确认游标 | 有序、脱敏、可去重的事件；不能跨用户订阅 |
| 中断操作 | 操作 ID、幂等键、明确停止意图 | 受理回执；实际结果由后续状态确认 |
| 回答待处理请求 | 请求 ID、用户回答、幂等键 | 已受理或明确过期、冲突、权限错误 |
| 创建分支关联 | 来源消息、分支基点、用户身份 | 经验证的分支任务及文件基点 |
| 获取产物 | 产物版本、用户身份 | 有权限校验的内容与元数据，不暴露对象存储密钥 |
| 确认同步结果 | 目标聊天、消息、事件或文件映射 | 可持久恢复的同步回执；不得代表执行已完成 |

### 12.2 最小关联信息

| 信息域 | 必需语义 |
| --- | --- |
| 宿主 | 独立实例 ID、受信来源、插件协议版本、启用状态 |
| 用户 | 外部用户 ID、LinkSense 用户 ID、首次匹配依据、绑定状态 |
| 聊天 | 外部聊天 ID、实际用户、分支或父链基点、LinkSense 任务 ID |
| 操作 | 外部用户消息与回复消息 ID、操作类型、幂等键、内容摘要、受理操作与轮次 ID |
| 同步 | 来源事件 ID 与顺序、已确认游标、目标消息、投递状态和状态版本 |
| 问答 | 请求 ID、任务和轮次、类型、有效状态、回答记录的幂等身份 |
| 文件 | 两端文件 ID、产物版本、所有者、校验值、传输状态和保留策略 |

标识由对应权威系统生成和校验，不能从模型回答提取用户或任务身份。内容摘要仅用于一致性检查，不得在日志中记录原始正文和附件。

### 12.3 错误与协议规则

边界数据使用 Zod 或宿主相应成熟验证库校验。集成错误返回稳定错误码、可本地化参数和关联 ID，不向用户返回堆栈、SQL、内部地址或原始服务错误。

至少区分未认证、来源未受信、身份冲突、账户禁用、权限不足、额度不足、忙碌、幂等冲突、附件无权限、文件传输失败、目标已删除、请求已失效、连接不可用和版本不支持。可重试标记只描述相应接口操作，不授权重新执行整轮任务。

协议版本与宿主、插件版本分开记录。尚未支持的格式应明确拒绝并给出升级或恢复说明，不堆叠旧路径和静默回退。版本变化对存量关联和任务的影响必须先验证，再决定数据升级方式。

## 13 配置与部署

### R14 管理配置

| 配置位置 | 配置内容 |
| --- | --- |
| Open WebUI 插件 | LinkSense 服务地址、登记宿主身份、服务凭证、连接和读取超时、插件启用范围 |
| LinkSense | 可信宿主登记、凭证轮换和撤销、邮箱信任策略、自动开通开关与普通用户默认策略 |
| LinkSense | 并发与额度策略、传输限制、结果同步策略、数据保留策略、审计配置 |
| 双方部署 | 受控网络访问、TLS、反向代理流式传输配置、必要的双向调用连通性 |

管理员一次配置后，普通用户不需要提供 LinkSense 密钥。插件首次启用前必须检查配置完整性、认证和必要接口连通性；检查不能执行用户任务。

服务地址是管理员配置，不接受聊天输入任意覆盖。引用远端文件时要限制来源、重定向、大小和超时，防止利用集成访问不允许的网络目标。

每个发布版需列明支持的官方 Open WebUI 版本和功能前置条件。开发基线为 v0.12.0，不等于承诺支持所有旧版或未来最新版。宿主升级后按兼容矩阵验证，不能自动把版本号较新理解为兼容。

### R15 安装升级停用与卸载

- 交付原生可导入插件及完整配置说明，不要求手工修改宿主文件。
- 在全新官方环境验证安装，并在已有用户、聊天和附件的环境验证升级。
- 插件与 LinkSense 升级顺序、协议检查、存量绑定和正在执行任务的处理方式必须明确。
- 停用集成应拒绝新的接管请求并撤销对应授权；对在途任务明确按配置保留执行或由管理员显式停止，不能假装已取消。
- 卸载不自动删除 LinkSense 用户、任务和产物。需要清理时列出数据范围并单独确认。
- 回退方案不能通过恢复旧源码补丁实现，也不能在执行是否存在不明时重发任务。

## 14 非功能要求

### R16 语言与可访问性

插件和 LinkSense 新增的用户可见文案支持 `zh-CN`、`en-US`、`es-ES`、`pt-BR`、`fr-FR`、`ja-JP`，默认和缺失语言回退为 `zh-CN`。复用项目语言定义；宿主语言代码不一致时集中映射。

状态、错误、问题、文件说明和管理配置标签使用语义化键。正式用户文案不暴露 Pipe、事件游标、内部 ID 等实现概念。测试六种语言的键覆盖、插值、回退及切换后的显示；原生入口和对话在桌面、移动端及键盘操作下可用。

### R17 可观测性与资源边界

结构化记录宿主、内部用户、聊天、操作、轮次及关联 ID，用于定位失败；默认不记录用户正文、附件内容、凭证、带授权的下载 URL 或完整工具响应。

应能分别观测受理耗时、排队耗时、首个进度、首段正文、执行时长、产物同步时长、重连次数、中断确认时长及同步积压。不能用模型执行时间掩盖插件或传输延迟。

外部调用有超时与取消，重连有界退避，上传和事件消费有背压，重放有分页和去重。多工作进程共享的关联、游标、锁和计数不得仅存进程内存。慢客户端不得无限积压内存或阻塞其他用户。

性能数值需在原型基线后确定，交付前冻结测试环境、并发数、文件大小、长任务时长、可接受延迟和失败率；当前不把未测量数字写成产品承诺。资源不足必须明确反馈，不能无界等待。

### R18 版本与存量资源

同时验证新安装和升级后的真实可用性。至少覆盖缺少新关联字段的旧用户和聊天、旧文件记录、已有禁用用户、已有外部身份、旧插件产生的关联及在途操作。

不增加无明确期限的兼容层或静默回退。若升级需要数据转换，使用正式向前迁移和经验证的升级流程。禁止要求用户通过重建账号、重新上传文件或重建聊天来隐式修复升级问题。

任何会丢失数据、改变必填字段、唯一性、字段类型、枚举或硬删除策略的变更，必须先说明具体影响并确认历史兼容要求。本文确认不等于授权删除历史数据或执行迁移。

| G03 身份自动开通 | 可信邮箱证据、自动匹配、新建、禁用拒绝、并发及越权测试 | 无可靠邮箱信任来源时阻断自动合并设计 |
| G04 可靠停止 | 覆盖多种取消时机，观察 LinkSense 实际终态，区分刷新与停止 | 不能只以宿主停止输出作为通过 |
| G05 恢复与确认 | 双端重启、断线和弹窗刷新后在原聊天恢复，不重复执行 | 必须解决或取得具体交互范围变更确认 |
| G06 分支文件状态 | 编辑和分叉后的文本与工作目录基点一致，原分支不受污染 | 禁止仅用聊天复制宣称分支支持 |
| G07 文件闭环 | 有权限的导入、真实生成、预览、下载、版本与重放去重 | 不能只展示文件名或无权访问的 URL |

建议开发顺序：先验证 G01、G02、G04、G05、G06 的扩展机制，再实现身份和最小文本多轮闭环，随后接入进度、问答和附件，最后完成权限、并发、异常恢复、升级及六语言验收。每一阶段都保持可运行的版本，但未通过全部发布门槛前不得宣称正式交付完成。

## 18 测试与交付标准

开发阶段新增和修改的行为均配套单元测试。LinkSense 使用 Vitest 和 Fastify inject；插件使用宿主兼容的 Python 测试工具并通过 uv 管理环境。先运行受影响测试，再按共享契约影响扩大到类型检查、lint 和构建。

至少保留三层证据：

1. 规则与转换测试：身份绑定、幂等、状态映射、事件顺序、文件去重、问答与授权。
2. 官方宿主集成测试：真实插件加载、中间件路由、数据库持久化、停止、文件接口和进程恢复。
3. 浏览器端到端验收：输入框选择、连续多轮、进度、文件预览、刷新和确认交互。

测试环境与模型、文件和外部服务应受控，不使用生产用户数据。浏览器自动化按项目要求仅在明确授权的验证任务中执行；如果尚未执行，发布验收记录必须标为未通过或待验收，不能用单元测试代替。

交付包应包含插件文件、版本与协议清单、校验信息、安装配置说明、LinkSense 变更、迁移说明、测试和结果、故障恢复步骤及已知限制。源码和发布包不得包含密钥、用户文件或开发机路径。

## 19 尚待落实的技术决策

已确认的是产品目标和硬性边界，下列决策必须在对应实现前形成明确方案与证据。

| 决策 | 必须回答的问题 | 对应门槛 |
| --- | --- | --- |
| 身份信任协议 | 如何证明宿主和邮箱可信，如何签发受限委托身份与撤销 | G03 |
| 接管预处理 | 如何避免原模型工具和知识处理干扰，同时保留原始输入附件 | G02 |
| 原生停止桥接 | 如何覆盖取消时机缺口，并区分停止与进程关闭 | G04 |
| 进程重启恢复 | 采用何种官方扩展触发核对与续接，是否能自动恢复 | G05 |
| 待确认恢复 | 原浏览器会话消失后如何在原聊天恢复准确应答 | G05 |
| 分支工作目录 | 当前原生执行能力如何保证历史文件状态和分支隔离 | G06 |
| 产物同步 | 如何以实际用户身份注册文件、保证去重与长期可访问 | G07 |
| 支持矩阵与性能 | 具体版本、部署形态、并发、文件限制和验收阈值 | 全部 |

存在这些待决策项不授权突破 R01，也不表示可以把已确认功能从正式范围删除。若验证发现无法满足，必须在完整开发前给出具体影响并取得产品决策。
