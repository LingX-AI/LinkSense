# 用户项目运行环境调整

## 已确认的范围（2026-09-15）

- 一个用户共用 Docker Worker、HOME、CODEX_HOME、工具、插件、Skills、MCP 和个人登录状态。
- 原任务分类升级为项目，同一项目任务共用项目目录；无项目任务使用用户公共工作目录。项目不构成同用户任务之间的权限边界。
- 任务继续分别保存对话和执行状态；移动项目只改变后续工作目录，不搬走源项目文件；运行中不能移动。
- 删除任务保留项目文件，移除项目和删除文件分别处理。
- 应用分别支持分享独立副本和发布服务。副本使用自己的资源；发布服务运行在独立于个人环境的服务环境，并保护访问者之间的数据。
- 发布版本不随草稿修改而改变；发布服务不自动授权复制。
- 空闲 15 分钟回收 Worker、保留用户数据；正在执行任务或存在用户进程时不回收。
- 系统环境方案 A：公共基础镜像，用户安装和修改保存在 HOME 或项目中。
- 历史数据方案 A：保留分类归属、任务、原生会话、文件、应用授权、嵌入链接及外部会话；允许一次性转换，不保留长期旧运行路径。

## 数据切换约束

正式转换前停止写入并创建可恢复的数据库、用户目录和相关对象数据备份。转换先生成清单并验证冲突，完成后验证旧会话和嵌入入口继续可用，再移除已验证替代的旧目录。不得用重建、清空或跳过旧数据测试来代替用户选择的保留方案。

本文件记录实施范围和验证进度；勾选项必须以实际执行结果为依据。

## 2026-09-17 移除保持运行设置

移除个人设置中的“保持工作环境运行”开关、API `/me/environment` 和 Controller `/environment` 接口，以及对应的设置读写逻辑。前端、API 和 Runner Controller 应同步更新；旧页面请求已移除的接口会返回 404，刷新页面后使用新设置页。

已有 `control/environment.json` 不再读取或写入，无需数据库迁移，也无需重建用户环境。此前开启保持运行的环境，在没有执行中的任务、原生进程或用户进程时，恢复按配置的空闲超时回收；网站、服务等用户进程仍受现有活动检测保护。回收仅停止并移除 Worker 容器，持久化文件和个人配置保留。

## 发布和复制

发布版本固定应用提示词、模型选择、交互页面版本、插件/Skill 文件及依赖资源的选择。知识库内容、MCP 连接设置和凭据仍由对应资源维护，更新或撤销后按当前授权生效，不会把凭据写入发布快照。作者更改草稿不改变现有发布版本，已有任务继续使用创建时的版本。

交互式应用的新任务同时固定页面和运行说明。历史任务原先绑定旧页面时，转换会为这些页面创建对应的发布版本，保留原任务的页面和说明；应用的当前发布入口保持不变。共享使用者只能访问已发布页面，不能通过指定页面编号打开未发布的草稿。

复制必须另行开放。副本创建使用者自己的应用、插件和 Skill 文件；不复制作者的凭据、MCP 连接和私有知识库。需要这些连接的副本先停用，使用者按照使用说明完成配置后启用。嵌入页面继续调用发布服务，使用独立访客身份，不创建完整成员账号。

## 一次性切换操作

1. 在旧版本中结束运行中的任务，并等待已受理的启动请求完成，再停止 API、调度器和所有 Worker。转换工具检测到运行中任务或尚未完成的启动操作会中止，不会删除或重放这些请求。使用既有备份流程备份 PostgreSQL、用户目录和对象存储，验证备份可恢复。
2. 执行 `pnpm db:migrate:deploy`。迁移保留分类/任务编号与顺序、应用授权、嵌入标识及密钥。`20260915120000` 会将虚拟访客账号的配额和偏好转移至外部会话，然后删除这些虚拟账号及 `users.account_type`；若发现它们持有个人资源，迁移会中止，必须先核实资源归属。
3. 设置 `DATABASE_URL` 和 `LINKSENSE_USER_DATA_ROOT`，运行 `pnpm --filter @linksense/api runtime:convert-projects --backup-directory=/同一文件系统/唯一预检目录`。默认只预检并保存清单；用户目录不变。
4. 预检通过后，以另一个未创建的备份目录运行同一命令，加上 `--apply --workers-stopped --database-backup=/已验证的数据库备份文件`。Linux 环境须以 root 运行，以保留容器用户和监督进程的文件权限。
5. 工具合并个人原生会话及工具目录，把旧任务文件放入项目的 `imports/<task-id>`，同步附件引用，将应用任务放入服务空间。应用版本使用原先分配的版本编号补齐快照。已删除任务的工具目录保存在 `control/recovered-task-homes`，不激活其中无法确认归属的登录状态。替换的目录保存在备份目录的 `original-users`；不会由运行时读取。
6. 若进程中断，保持服务停止，使用同一命令的 `--recover --workers-stopped --backup-directory=原备份目录`。工具对照数据库提交状态恢复未完成的目录切换，或确认已提交切换。出现冲突时保留备份并人工核对，不能带着冲突启动旧/新 Worker。
7. 启动升级后的服务，验证原任务继续执行、历史附件可下载、应用服务与原嵌入入口可用后，按备份保留策略清理旧目录。需要完整回滚时，同时恢复升级前的数据库、用户目录、对象存储和对应程序版本。

如果不同任务保存了不一致的账号配置、同一原生记录存在不同内容、原生数据库结构不同，或文件链接逃逸源目录，转换会中止。不会自动选择一个登录身份或覆盖一份历史。先在备份上核对并解决冲突，再以新的目标目录预检。此操作只在停机维护期间运行，不是常驻兼容层。

### 多版本历史环境的预检

- 原生 SQLite 结构不同：先在备份副本上使用项目固定的 Codex 版本完成原生升级，核对原有记录，再将包含 WAL 的状态检查点保存为独立数据库文件。不得只复制主文件而遗漏尚未合并的 WAL。
- 模型网关、内置 MCP、运行模式控制的 Skill 设置，以及 LinkSense 管理的插件市场路径由运行器重新生成。原配置完整归档；私有 MCP 和插件配置存在实质差异时仍中止转换。
- 同一会话的日志仅在旧文件是新文件的完整字节前缀时保留较长版本；较新的任务专属数据库记录可以替代旧共享副本。相同时间且内容不同的记录仍视为冲突。
- 原生日志编号、安装编号和目录扫描游标属于单个环境，不作为全局历史合并。原数据库保存在 `control/native-home-imports`，其中损坏的诊断日志也保留原文件，不阻塞完好的会话数据库转换。
- 记忆数据库中的原始记录合并保留；各环境生成的记忆摘要及 Git 基线完整归档，活动环境保留一套完整基线，后续由 Codex 重新整理。此处理遵循 [Codex 0.154.0 原生记忆流程](https://github.com/openai/codex/blob/rust-v0.154.0/codex-rs/memories/README.md)。
- 已删除任务的环境直接归档到 `control/recovered-task-homes`，不升级或激活其配置。重复的系统生成链接重新定位到用户环境；自建文件和私有配置不按缓存处理。
- 原生 `.codex/tmp`、`.codex/.tmp` 和进程锁不复制到新目录或逐任务归档，避免重复临时插件目录占满磁盘；原文件仍随切换前的完整目录保留用于回滚。已安装插件、凭据、会话、记忆和用户自行创建的临时目录均保留。

正式转换内部会先完整构建和校验新目录，再切换数据库引用和活动目录。预检中止时检查备份目录中的日志，保持服务停止，解决已确认的冲突后使用新的目标目录重试。

## 验证命令与边界

- `pnpm test`：共享契约、后端、Runner、前端组件/交互、浏览器、文档和部署测试。
- `pnpm typecheck`、`pnpm lint`、`pnpm build`：全仓类型、静态检查及生产构建。
- `pnpm test:runtime:projects:postgres`：临时 PostgreSQL 容器，从旧迁移集和代表性历史记录升级，验证目录转换、附件、原生编号、项目删除、外部会话及交互页面版本。
- `CODEX_BIN=<0.154.0 路径> pnpm test:codex:shared-home`：真实原生进程共享 HOME、并发任务、历史 SQLite/会话转换、恢复及项目目录切换；模型回复由本地测试服务提供。
- `CODEX_BIN=<0.154.0 路径> pnpm test:codex:native-plugin-refresh`：真实原生插件安装、更新、发现和卸载。
- `LINKSENSE_TEST_WORKER_BASE_IMAGE=<已构建的 Worker 镜像> pnpm test:runtime:docker-shared-home`：生产容器规格启动、共享项目、删除保留文件、容器重建持久化、后台进程检测、服务环境与认证分离，以及 macOS 无法直接运行的 Linux 权限回归。

这些验证使用独立临时目录、容器和测试数据，不对真实用户目录执行转换，也不调用真实外部模型、MCP 或第三方账号。正式切换仍须执行上述停机、备份、预检、转换和入口验证步骤。
