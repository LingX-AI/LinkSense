# 交互式应用任务状态恢复

## 范围与接口

SDK 1.2.0 在现有 v1 地址增加 `tasks.getState()` 和 `tasks.onStateChange(handler, onError?)`。两者使用已有 `tasks:write` 权限；Manifest 的 `sdk_version` 仍为 1。

`GET /conversations/:id/interactive-task-state` 校验登录、会话所有者、交互式应用身份和会话当前记录的包权限，再从现有会话详情投影公开状态。复用启动意图、轮次、文件、待处理请求和错误事件；不新增表、字段或任务状态持久化，也不重试或重放执行。

公开字段：`status`、`turn_id`、`file_ids`、`can_submit`、`interrupt_requested`。不返回提示词、用户答复、内部错误详情、凭据或存储路径。`can_submit` 是展示提示，实际提交仍须通过现有服务端并发检查。

宿主使用 TanStack Query 管理查询，按生命周期通知、窗口聚焦、恢复网络更新；忙碌时每 5 秒只读校准。生命周期刷新先取消旧查询，避免受理前的查询覆盖新状态。向 iframe 发送独立于业务事件的状态消息，带当前页面实例内递增的版本；SDK 缓存最新状态、丢弃旧响应、支持取消订阅和读取错误回调。状态通道不声明或伪造应用自定义业务事件。

应用初始化先订阅、读取初始状态，再启用操作。已受理文件即使仍是 staged 也不可再次提交；已绑定文件保留展示但不可移除。停止请求不等于已停止。业务结果继续通过现有持久化事件回放，按事件 ID 去重、按轮次区分；完成状态到达后仍接收尚未回放的结果。

## 文档、模板及版本

- 中英文交互式应用开发帮助增加状态字段、恢复顺序、错误处理和已有应用更新说明。
- 内置 LinkSense 交互式应用开发 Skill 增加状态恢复、文件占用、结果去重和回归验证指引。
- 新建应用模板默认先恢复状态再允许提交；通用研究简报示例增加状态恢复、停止确认、已提交附件展示和多轮结果分组。
- 同步更新内置资源内容指纹，使后续资源准备使用新的文档与 Skill。

已有 Manifest 和 SDK 方法继续可用，旧历史任务无需数据转换。平台不会自动修改已发布应用源码；已有应用要恢复内部控件，需要接入新方法并正常发布、安装更新。已有任务仍按原有包版本采用规则更新，不能仅凭刷新就假定旧页面代码已升级。本次没有修改用户的具体业务应用。
