# 聊天富内容

将完整的 `json-render` 代码块与正常的 Markdown 正文放在同一条回答中。默认模式的 Core MCP 工具 `get_rich_output_catalog` 提供当前组件目录、参数和示例。它只读取规范，不生成数据、不执行操作。首版支持带依据的研究摘要、可切换的方案对比，以及可在柱状图或折线图与可排序表格之间切换的数据分析。

- **存储与升级**：块保存在原有消息正文中，结构为 `{ version: 1, summary, spec }`，不需要迁移数据库。现有 Markdown、代码、Mermaid 和 HTML 预览继续按原方式呈现。更新时先让 API 与 Web 支持新格式，再让 Runner 开始生成，避免旧读端把 JSON 当作普通代码块。扩展目录时保留已保存的第 1 版结构。
- **边界**：[共享 Zod 契约](../../packages/shared/src/rich-output.ts) 限制大小、树结构与每个组件的参数。Web 先校验完整内容，再按需加载 json-render `core`/`react` 渲染器；组件复用现有 Base UI 与 Recharts。状态只用于本地选择、展开和排序。依据中的引用编号须能解析到该回答已有的引用；卡片不直接接收资源链接，不会启动工具、提交表单或代替用户确认。
- **降级**：生成期间显示整理状态。不可用的块不影响正文；有效内容可在渲染失败时显示明细文本。复制和纯文本分享保留可读内容，外部消息渠道与自动化通知接收摘要。空值会显示为缺失，零值保留为零。

可用示例问题：“用富内容卡片比较先做验证和一次性建设两种方案，列出各自的优势与取舍。”涉及实际数据时，先提供附件或可核对的数据来源。首版不包含逐步更新图表、交互结果的跨设备同步或独立应用发布。
