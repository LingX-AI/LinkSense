# 聊天富内容

将完整的 `json-render` 代码块与正常的 Markdown 正文放在同一条回答中。默认模式的 Core MCP 工具 `get_rich_output_catalog` 提供当前组件目录、参数和示例。它只读取规范，不生成数据、不执行操作。当前支持研究摘要、方案对比、关键信息、事件时间线、建议步骤、分组与折叠阅读、临时检查清单、图表与表格数据分析，以及已注册产物的图片集与文件卡。

- **存储**：块保存在原有消息正文中，结构为 `{ version: 1, summary, spec }`。现有 Markdown、代码、Mermaid 和 HTML 预览继续按原方式呈现。
- **边界**：[共享 Zod 契约](../../packages/shared/src/rich-output.ts) 限制大小、树结构与每个组件的参数。Web 先校验完整内容，再按需加载 json-render `core`/`react` 渲染器；组件复用现有 Base UI 与 Recharts。选择、展开、勾选、排序和筛选只影响当前视图。依据中的引用编号须能解析到该回答已有的引用；资源组件只接收文件 ID，预览与下载经过既有后端鉴权，不接收模型生成的地址，不会启动工具、提交表单或代替用户确认。
- **降级**：生成期间显示整理状态。不可用的块不影响正文；有效内容可在渲染失败时显示明细文本。复制和纯文本分享保留可读内容，外部消息渠道与自动化通知接收摘要。空值会显示为缺失，零值保留为零。

可用示例问题：“用富内容卡片比较先做验证和一次性建设两种方案，列出各自的优势与取舍。”涉及实际数据时，先提供附件或可核对的数据来源。首版不包含逐步更新图表、交互结果的跨设备同步或独立应用发布。

## 组件与数据

目录包含 17 类：Panel、Grid、Tabs、Details、Text、KeyValue、Timeline、Steps、Checklist、MediaGallery、ResourceList、Callout、Evidence、Comparison、Metric、DataTable、Chart。Panel 是唯一根节点；只有 Panel、Grid、Tabs、Details 可以包含子节点。每块仍限 65,536 字符、40 个元素及深度 6。

- Tabs 用于同一结果的不同视图，`props.tabs` 接受 2–5 个 `{ id, label }`，ID 必须与 `children` 顺序一致，标签各不相同。第一项默认选中；方向键移动焦点，Enter 或空格切换。每个标签对应一个子块，多个子块可放在 Grid 中。
- Details 用于计算过程、示例等补充内容。`props.title` 是展开按钮的名称，`children` 至少有一项，默认收起，各折叠区独立。把主要结论和必要风险放在可见正文或 Callout 中；有引用的依据继续用 Evidence。
- Evidence 展开后保留证据说明，并为匹配到当前回答的 `citations` 显示知识库、文档和已记录的页码或章节。点击进入现有的引用预览，由服务端检查当前权限。引用编号按正文中不同引用片段首次出现的顺序分配，不是检索结果的排名；找不到匹配的编号时不生成链接。旧格式无需改动，复制和公开分享保留证据正文，不追加私有引用的文档信息或预览入口。
- Checklist 的 `items` 接受 1–30 个 `{ id, label, detail? }`，ID 在列表内唯一，初始全部未勾选。当前卡片挂载期间，切换标签或收起详情不会清除勾选；刷新或卡片重新挂载会重置。勾选不会提交、代表任务进度或成为分享内容。需要 AI 获取用户答复时继续使用 `request_user_form`。
- MediaGallery 的 `items` 接受 1–12 个 `{ fileId, alt, caption? }`。用静态缩略图网格展示本会话的已注册图片产物，按容器宽度排列；沿用图片懒加载、现有大图预览和下载。`alt` 描述图像，`caption` 解释它与回答的关系。图片格式沿用现有产物预览范围，不新增轮播或媒体引擎。
- ResourceList 的 `items` 接受 1–20 个 `{ fileId, label, detail? }`。`label` 和 `detail` 是回答对交付物的说明；真实文件名、类型、大小和可用操作来自当前会话中已加载的文件记录，沿用原有产物卡的预览、下载和忙碌状态。两类组件的文件 ID 在列表内不区分大小写地唯一，必须使用 `register_artifact` / `generate_image` 返回的 **file_id**，不能使用 artifact_id、附件 ID、预览 ID、路径、URL 或 base64。有效 UUID 不能授予资源权限，未知、已删除或不可下载的文件只展示说明和不可用提示。
- KeyValue 的 `items` 使用 `{ id, label, value }`，适合结构化元数据，`null` 表示缺失。Timeline 的条目使用 `{ id, title, time?, detail? }`，按给定顺序展示；时间标签保留已知精度和时区，不强制补成精确时间。Steps 使用 `{ id, title, detail? }`，展示建议或操作顺序，不表示真实执行状态。三种列表最多 30 条，ID 在列表内唯一，空列表有明确提示。
- Metric 保留原有 value/unit/detail，可选 `period` 和 `comparison: { label, change, unit? }`。change 是有真实比较基准的带符号变化量，单位明确区分百分比、百分点或其他单位；组件不自行推断涨跌是否有利。
- DataTable 保留原来的无类型列和混合值格式。列可增加 `type: "text" | "number" | "date"` 和 `unit`；声明类型时，非空值必须匹配，日期是有效的 `YYYY-MM-DD`，不进行时区换算。`filterable: true` 启用当前快照内的筛选，显示匹配数与总数，不查询其他数据。排序保留原始数值、日期语义和稳定行 ID，缺失值在两个方向均排在最后。
- Chart 继续接受旧版 `points: [{ id, label, value }]`。多序列使用 `series: [{ id, label }]` 与 `points: [{ id, label, values }]`，values 按 series 顺序对应，长度必须一致；支持 2–6 个系列、最多 100 个点，所有系列共用明确单位。`stacked: true` 仅用于柱图；折线通过不同线型辅助区分。图例、提示、表格替代和文本快照保留所有系列及缺失值，零值保持为零。

## 兼容与验证

原有富内容消息无需迁移或重建。既有组件的新增元数据均为可选，旧单序列图表继续有效；已经保存的块仍使用 `version: 1`。先更新 Web、API 和其他文本读取端，再让新版 Runner/Worker 生成新类型；旧严格解析器遇到新组件或字段可能拒绝整个块，回退时须保留新格式读取能力。复制和公开分享保留所有标签页、折叠内容、检查项目和数据明细；外部消息渠道继续使用摘要。

资源块的文字投影保留模型提供的图像描述、文件说明和标题。公开快照生成和读取时都会移除块内的文件绑定，不追加授权记录中的文件名、大小或预览与下载地址；所有者选入快照的文件元数据仍按既有规则处理。文件注册与图像生成工具要求的最终交付 Markdown 链接继续保留。只有可见的富资源组件才替代同一轮回答中对应的自动产物卡和生成图；切离标签页、收起详情、卸载或渲染失败时恢复原入口。任务概览保留独立的文件入口。缩略图加载失败仍可下载。会话分叉将有效富内容中的 fileId 重映射到复制后的文件，不替换正文和普通 JSON 中的裸 ID。

聊天在切换视图、展开、筛选等交互时暂停自动跟随，避免卡片高度变化将阅读位置拉到底部。验证应覆盖旧结果、无效子节点、文本降级、六语言、桌面与窄屏、键盘焦点、内容高度变化及刷新后重置。

受控回归见 Shared、API、Web 的富内容测试及 `e2e/app-shell.spec.ts` 中 `rich AI output` 用例，覆盖预览、下载、键盘与窄屏、失效资源、公开投影和会话分叉。它们验证给定输出的呈现；模型是否选择该组件须单独用自然提问验证。
