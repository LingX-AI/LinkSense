# LinkSense UI 设计基线

本文件是后续 UI 开发的仓库入口，和主题变量、共享组件一起使用。2026-10-24 已将基线扩展到现有 Web 页面的共享外壳、表单、列表、弹窗和聊天呈现；有稿的页面参考个人 Figma 副本，其他页面复用本规范。2026-10-28 对照新的个人副本补齐侧栏、图标、颜色及页面家族差异；本轮来源与验证见 [适配复核](linksense-ui-fidelity-followup-2026-10-28.md)。此前覆盖见 [适配盘点](linksense-ui-adaptation-inventory-2026-10-23.md)。297 个设计画板包含状态变体，不等于 297 个业务页面。

## 使用顺序

1. 保留真实业务、接口、资源权限、Codex 原生生命周期、可访问性与已有用户偏好。
2. 有明确稿件时参考相应节点；缺稿时复用本文件、语义 token 和同类页面，不以补画 Figma 为前置条件。
3. 实现存在约束时完成可行部分，说明实际差异；常规布局、交互和可读性问题应直接修复。
4. 普通页面无需重新读取整份 Figma。新稿、规范更新或现有基线无法解释的关键视觉差异，再按需读取相关节点。

## 代码入口

| 能力 | 入口与约定 |
| --- | --- |
| 主题与排版 | `apps/web/src/index.css` 中的 `:root`、`.dark`、`@theme inline` 是取值来源。复用语义色、标题层级、字体、圆角和间距，不在页面散布近似颜色；不另维护一张数值表。 |
| 页面与顶栏 | `components/shell/page-layout.tsx`、`page-top-bar.tsx`、`settings-shell.tsx` 管理顶栏、内容宽度、页面标题、说明和操作区；设置内复用 PageLayout 时不重复显示顶栏。 |
| 基础控件 | `components/ui/` 复用 Base UI 的键盘、焦点、禁用、表单和弹窗语义。Input、InputGroup、PasswordInput 默认描边；嵌套或透明编辑控件可显式使用 `variant="default"`，避免双重边框。 |
| 分段标签 | `components/ui/tabs.tsx` 的 TabsList 默认采用 Segmented；插件中心一级导航用 `navigation` 下划线，资料库导航和自动化状态筛选用 `pills`。周期、分组、内容范围、运行位置、上传方式与认证方式仍复用默认变体；单个活动背景复用 Base UI 的容器内测量结果，由现有 Motion 平滑移动与缩放。路由会重建列表时，以稳定且唯一的列表 id 维持背景连续性；其他实例自动隔离。保持横向滚动、竖向标签、键盘和减少动态效果支持，不在页面叠加旧下划线或独立选中背景。 |
| 操作按钮 | 默认与 `brand` 使用实色主色及悬停色；保留已有紧凑尺寸和明确的图标按钮尺寸，不按一张画板统一放大所有密集操作。账号提交继续保留原有较大触达区。 |
| 卡片聚光 | `components/ui/card-spotlight.ts` 从 React Bits SpotlightCard 适配局部装饰；首页快捷卡、自动化模板、应用卡、站点卡、能力条目与知识库入口通过 `cardSpotlightProps` 复用。保留其 className 与现有类合并；仅精细指针悬停且未减少动态效果时跟随光点，键盘焦点使用静态边缘高亮。无常驻帧循环、额外布局容器或点击拦截，许可见 `THIRD-PARTY-NOTICES.md`。 |
| 设置分区 | `components/settings/settings-card.tsx` 的 `layout="split"` 将类别标题、说明和图标置于左侧，字段卡片置于右侧；随内容容器宽度堆叠。默认 stacked 仍用于管理表单等场景。两种排列共用四边相等的内边距，布局变体只调整排列和内容间隔。 |
| 账号访问 | `components/auth/account-access-layout.tsx` 统一品牌面板、语言选择、表单阅读宽度和归属标记；`AccountAccessHeading` 管理登录/找回的标题层级。注册、激活、重设密码、初始化与身份回调复用同一外壳。 |
| 聊天与输入 | `features/conversations/conversation-thread.tsx`、`conversation-composer.tsx`、`conversation-model-selector.tsx` 沿用原有消息、执行、输入和资源状态。项目选择器在输入工具栏内，创建项目只提交项目表单。 |
| 首页与共享页 | `new-task-welcome.tsx` 复用真实问候和提示词；`pages/shared-conversation-page.tsx` 复用首页渐变素材，展示标题、快照时间和只读说明。 |
| 文案与素材 | 新的账号、首页、设置分区及共享快照文案覆盖六语言。图片保存在 `assets/brand/` 和 `assets/home/`，不能使用临时 MCP 下载链接或整页截图作为运行界面。 |

## 视觉与响应式规则

- 整体采用浅色蓝灰工作区、白色卡片与顶栏、蓝色操作和选中状态。正文、辅助文字、边框与分隔线有各自语义；暗色通过相同角色适配。
- 区分页面主标题、分区标题、正文、字段标签、辅助说明。系统字体优先，保留本地 Inter / Noto Sans SC 等回退与用户字号偏好；不分发 SF Pro，也不承诺跨平台文字栅格化完全相同。
- 用 Tailwind 工具类完成页面布局、状态和断点。容器查询根据实际可用宽度调整卡片、设置分区与输入工具栏；少量 CSS 用于全局 token、复杂状态及既有聊天测量布局的衔接。
- 页面居中且有阅读宽度上限；宽数据表使用自己的水平滚动区，不能让整页横向溢出。弹窗宽度受视口约束，内容超高时滚动，保持关闭和提交可达。
- 普通弹窗使用轻量半透明遮罩与细边框，不模糊背景。搜索采用更宽的分组结果面板；项目、分享和确认弹窗复用同一视觉层级。
- 主题预览展示浅色、深色和系统模式，选择与本机持久化机制不变；字号输入保留原有范围和键盘行为，并展示实际字号的本地化示例文字。
- 手动切换主题时使用原生 View Transition，从视口右上角以圆形裁剪揭开新主题，约 650ms 缓入缓出，最终半径按视口对角线计算以覆盖全屏；浅色和深色均向外扩张。首次加载、颜色未变、减少动态效果偏好或浏览器不支持时直接应用主题。快速切换以最后一次选择为准。
- 长译文允许换行和自然增高。移动端隐藏装饰图，表单按自然文档流滚动；标题、菜单、模型名和资源名的截断只用于明确受限的区域，并保留完整内容的访问入口。
- 装饰图使用等比缩放与裁切，不能用独立百分比宽高拉伸。产品标志继续复用现有自定义品牌和暗色资源；不固定设计稿中的用户姓名、头像或示例数据。
- 保留语义标签、错误关联、密码显隐、自动填充、可见焦点和禁用说明。品牌蓝与选中表面遵循当前 Figma；白色小字动作、小字蓝色前景及辅助文字单独使用可读性语义色，具体例外见适配复核。图标使用 `DesignIcon` 引用的原始 Figma SVG，保留路径、尺寸和线宽；应用、项目等动态身份按实际资源显示。

## 页面家族的实现约定

### 任务、项目、搜索与分享

侧栏沿用真实置顶、项目、最近任务和账户功能。分组标题为 12px 常规字重、40px 点击区；箭头和操作在悬停、键盘聚焦、菜单展开或触屏时显示。任务为 40px 行高，项目子任务整体缩进 24px；菜单和信息气泡锚定行右侧、顶部对齐、间隔 8px。子菜单保留原生触发项锚点，偏移计入父菜单内边距，保证间距和原生悬停交互一致。Ctrl/⌘K 打开并聚焦搜索，包括侧栏收起及窄屏；指针在窄屏打开搜索仍沿用不自动弹出键盘的行为。默认宽度参考设计稿，已有本地保存宽度继续生效。首页提示卡只填入草稿，不自动发送；欢迎区初次停在顶部，聊天仍按原有滚动策略定位最新消息。

欢迎区和快捷卡片按实际内容容器宽度分档：窄容器采用较小标题、间距与横向紧凑卡片，中等容器使用较小的纵向卡片，宽容器保留完整尺寸。输入框在窄工作区收紧内边距与空态高度，输入内容仍可自然增高至已有上限；工具栏按可用空间自然换行，嵌入的项目选择器不得继承上方项目条的整行宽度，不能强制拆出额外一行。

新任务页的欢迎区、快捷卡片与底部输入框共同复用 `--app-reading-width` 的居中限宽，不覆盖成整屏宽度；窄屏按可用空间收缩。底部归属标志与输入框必须保持互不重叠，验证需覆盖约 1720px 的切换点和超宽窗口。

新任务欢迎区右侧装饰图必须以原 `welcome-orb.svg` 为视觉基准，保留形状、点阵、尺寸和配色，不用程序生成的球体替换。`welcome-orb.tsx` 在原图上增加轻微浮动、18 秒一轮的小幅来回旋转、沿原 SVG 遮罩流动的高光，悬停时小幅透视倾斜、跟随鼠标并在原图点位间显现局部连线；移开后平滑恢复。复用已有 Motion，附带键盘可达的暂停/继续控制；减少动态效果时静态呈现，窄屏保持隐藏。其他引用同一 SVG 的页面保持原有表现，不关联真实 Agent 执行状态。

聊天阅读区、用户消息、模型选择和输入区遵循统一边距与层级。消息 Markdown、运行中/停止/失败、审批、结构化表单、计划、目标、附件、来源、产物、Office 预览及浏览器面板继续由现有代码和 API 决定；不添加假的执行状态、模型响应或重试策略。项目弹窗的提交事件不能冒泡到外层聊天表单，回归须验证创建项目不发送草稿。图片预览保留原生懒加载、缓存和鉴权；初次解码在图片尚未加载时被拒绝，不应立即判为损坏，等待本次 load 后再完成解码，并清理卸载监听。

分享保留真实的公开链接与固定快照语义。Figma 的“仅有权限的人可查看”不适用于现有分享 API，不能照抄；对话预览、任何持链接者可访问的提示、脱敏和只读限制继续保留。公开页展示快照生成时间及后续消息不包含在内的说明，不显示不存在的作者字段。

### 自动化、插件中心和资料库

自动化复用现有计划、启停、立即执行、监控规则、模板和编辑侧栏；模板以卡片呈现，不按静态示例创建定时任务。插件中心的模块导航位于页面标题之后，发布管理在顶栏；应用、插件、技能、连接器、MCP 与发布审核使用已有数据和权限。

资料库复用同级内容导航、搜索、过滤、列表与状态；文档管理、上传、分享授权、任务产物、站点、引用和预览继承共享表单、表格与弹窗规范。实际列表行保留现有资源信息及操作，不能用稿件示例代替真实记录。

### 个人与管理设置

常规、个性化与密码设置采用可复用分区。自动命名仍在实际的“个性化”页；通知仅在用户主动启用后申请浏览器权限。资料页使用横向身份卡与明确的编辑/头像操作，保留现有五项统计、活动热力图及其他用量数据，不为了匹配示例删减实际能力。

设置标题和表单行按各自容器的实际可用宽度排列：不足 42rem 时标签、说明和控件上下堆叠，达到该宽度才左右排列。窄容器内选择器占满可用宽度，开关和短按钮保持自然尺寸；不以整屏宽度判断是否有足够的标签空间。

个人额度、凭据、MCP、消息渠道、反馈、归档，以及管理端用户、分组、角色、模型、用量、额度、资源、审计、系统设置、健康与更新页面复用共享外壳和控件。现有认证、授权和接口契约保持不变；应用自身内容与用户创建的 iframe 内容不属于外壳主题的改写范围。

管理后台的页面宽度由 `SettingsShell` 统一限制为 1440px，个人设置为 1200px，窄屏均自适应。页面和 Tab 不单独切换宽度；共享滚动区预留滚动条空间，避免长短内容切换时页面与分段标签横向跳动。

## 账号页静态呈现

登录及其他账号页直接静态显示文字、品牌图与表单。首次访问和客户端路由返回均不播放文字遮罩、面板展开、图片缩放或表单入场动效；保留提交和身份验证过程中的真实加载反馈。

## 设计来源和实际边界

当前工作副本为 [LinkSense 个人副本](https://www.figma.com/design/GfUnM6oiaNosrDDqZv19cK)，本轮读取时间为 2026-10-28。此前 2026-10-23 至 24 使用的副本为 `UeHSfgORGySQ6c6JbAcrR3`。代表节点与读取状态记录在适配盘点中。大画板返回稀疏结构时补读可见子节点；隐藏备份层不作为实现依据。

以下差异是实际适配：账号页较大的提交区域、跨平台字体、移动/暗色表现、真实的项目与通知入口、模板编辑侧栏、公开分享快照及管理表单。团队/奖励等仅存在于稿件而没有现成产品入口的内容不新增假功能；未配置模型、资源权限不足或第三方服务不可用时显示真实状态。

2026-10-24 的适配没有迁移基础技术栈、添加依赖、修改数据库、部署共享环境或写回设计稿。2026-10-28 后续发布结果见适配复核。常规页面后续可直接使用本基线；新的业务能力仍需相应需求与真实接口。

## 验证入口

全站 token 或共享控件改动应运行 Web 单元测试、类型检查和 lint，并运行受影响的浏览器检查。已有 Vitest 覆盖业务交互、六语言、授权呈现及失败路径；Playwright 覆盖账号、聊天、设置、管理表单和预览操作。

`e2e/app-shell.spec.ts` 新增 28 个页面入口在桌面浅色、窄屏浅色和桌面暗色的布局巡检，以及公开快照在桌面/窄屏的只读与 Axe 检查。模拟数据不替代真实邮件、SSO、第三方连接、AI 执行、数据库权限和生产升级验收。最新检查结果见适配盘点。
