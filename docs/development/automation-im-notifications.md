# 自动化 IM 结果通知

在新建或编辑自动化时，从「结果通知发送到」选择已绑定的飞书或机器人会话。默认关闭主动 IM 通知，保留现有站内和浏览器提醒。成功后发送本地化标题和最多 1200 字符的结果摘要；执行失败或中断时发送失败提示。通知不会重新执行 AI 任务，也不会自动发送完整附件。

## 接收位置与授权

- 只提供本人已绑定的会话，不接受任意外部群 ID。飞书个人助手只支持本人私聊。
- 机器人会话沿用现有发送者与群聊授权。企业微信和 Teams 的旧回复上下文不能可靠区分私聊和群聊，因此仅提供已允许群聊的渠道；钉钉使用已有的会话类型。
- 发送前在渠道发送锁内重查投递令牌、账号和任务；修改接收位置、关闭通知或删除渠道会取消等待和重试的记录。已开始的外部请求无法撤回。

## 部署与兼容性

1. 先执行 `pnpm db:migrate:deploy`，应用 `20261022090000_add_automation_notifications`。
2. 再部署 API 和 Web。迁移只新增可空配置列和通知表；旧自动化无需重建，旧请求缺失通知字段时保持关闭。

运行派发事务同时保存唯一通知记录，冻结当次接收位置。数据库处理令牌和过期时间负责多进程抢占；机器人通知由持有相应在线连接的 API 实例处理。排队运行按原始幂等键找到实际执行轮次，不丢失摘要；原生失败和中断不依赖成功完成时间。

发送异常最多尝试五次。飞书使用通知 ID 作为上游幂等键；其他渠道在上游已收到、但本地未确认的故障窗口仍可能重复送达。

## 验证

实现与审查阶段的相关单测、工作区类型检查、lint 和生产构建已通过。迁移曾在隔离 PostgreSQL schema 的显式事务中验证旧记录和新表默认值，随后整体回滚。

尚未对实际业务数据库执行部署迁移，也未向真实 IM 会话发送端到端测试消息。部署后需验证所选渠道的主动发送权限。
